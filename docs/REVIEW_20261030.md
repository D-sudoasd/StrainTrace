## Reproduced defects and resulting behavior

| Area | Reproduced failure | Corrected behavior |
| --- | --- | --- |
| Strain validity | A reflected or collapsed affine subset could pass the core strain gate while Agent extraction rejected its strains. A synthetic reflected field had 25/25 core strain points marked valid. | Reject nonpositive or numerically singular fitted/subset Jacobians consistently before strain smoothing and fitting. Retain raw correlation/displacement diagnostics. CSV, desktop maps, field helpers and numerical-quality masks agree. |
| Calibrated paths | A path requested in millimetres produced six valid CSV samples but zero plotted samples because the plot queried pixel coordinates. | CSV and position–time/frame plots receive the same coordinate system. Physical paths are labelled in millimetres. |
| Time and coordinate roundoff | `0.1 + 0.2` missed an exact mechanics sample at `0.3`; a nominal `0.2 s` bracket could exceed its own gap limit after subtraction; an inclusive calibrated 3×3 ROI retained only four of nine points. | Check both neighboring time samples and allow only floating-point roundoff in gap/coordinate comparisons. Truly out-of-range gaps and points remain unavailable. Exact calibrated path points also retain support at zero tolerance. |
| Repeated plots | Drawing a second image field on the same axes reversed its y direction. | Set the required direction explicitly for each image/calibrated plot. |
| Frame identity in the desktop | Saving, planning or creating a frame-index project with an identity-only mapping CSV incorrectly required timestamps. | Inspect actual supplied timing through the shared parser in the background worker. An identity map does not invent physical time. |

Preserve the original publication error; a recoverable backup supports a later successful rebuild. |

### Windows fixture correction

The first Windows CI run completed 622 tests successfully and skipped two,
but failed the legacy-quality compatibility fixture. That fixture used
`write_text` for the source API's canonical JSON, so Windows translated its
LF terminator to CRLF. The actual historical and current API both write
canonical JSON as binary UTF-8 bytes with LF. The fixture now writes those
exact source bytes and separately checks legacy report copies with both LF
and CRLF. This changes test coverage only; source checksum validation and
production code remain unchanged. The corrected report and publication tests
pass locally, with final Windows results attached to the follow-up merge.

### Runtime observation retained for follow-up

Some long CLI workflows under the review workspace intermittently saw an old
project lock reappear. Instrumentation recorded matching owner tokens, a
successful unlink and immediate absence; a later process read the same old
token. The recreation source was not captured. The same installed workflow
completed under `/tmp`, as did the final uninstrumented installed example and
independent source workflow. Smaller traced probes in both locations also
passed. This supports investigating filesystem visibility in the review
environment, but does not establish its cause. Lock ownership checks and
explicit stale-lock recovery were therefore preserved; this observation is
not represented as a fixed application defect.

These checks use synthetic inputs and existing software contracts. Private
experimental images and a new VIC-2D comparison were not available in this
review, so the changes do not establish experimental uncertainty or commercial
software equivalence.
