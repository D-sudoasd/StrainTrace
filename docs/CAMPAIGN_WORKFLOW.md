# 批次 DIC 与逐帧力学工作流

StrainTrace 的“批次项目”把采集身份、试样取点、图像分析和力学对齐串联起来。它和命令行使用同一套服务，仍由现有 ezdic_core 计算引伸计及二维 DIC。单批工作流和旧配置 v1 继续可用。

## 从桌面开始

1. 打开“批次项目”，新建项目或打开已有 project.json，选择原始数据根目录并扫描。原始文件只读，结果保存在项目目录。
2. 在批次表核对名称、原始帧号、时间来源及尺寸。采集批次不等于物理试样；未确认同根时不要共用面积。
3. 建议 ROI，在首、中、末帧预览中确认自由段、排除夹具，调整端点窗口。填写审核者并确认试样区域后才可运行。建议失败时手动圈选；系统不把自动识别当作材料身份判断。
4. 运行待处理批次。失败帧和不足三条有效引伸计的均值保持缺失，检查端点叠图和异常原因。可取消并恢复；已完成且指纹一致的批次会复用。
5. 导入载荷表，选择时间列、力列、插值模式和最大支撑间隔。预览后执行对齐，再导出并验证版本包。

## 命令行

执行 `straintrace campaign --help` 查看子命令，或使用 `python -m ezdic_cli campaign --help`。主要命令为 init、scan、import-keystone、propose-rois、approve-rois、run、align、export、verify。每个子命令的 `--help` 列出参数。

`examples/campaign/create_demo.py` 生成小型合成 TIFF、显式帧时间表及载荷表；示例不包含实验图像。项目配置独立于单批 run_config_v1，不要把两种文件混用。

## 后续实验如何复用

把上次项目的配置作为候选模板时，只复用分析方法、字段约定和质量检查策略。数据根目录、参考帧、ROI 几何、曝光时间、时钟锚点、面积与试样关联必须逐次核对。不能移植上次的审核记录。`init` 创建新的配置 v1；`scan` 建立新批次身份；先完成代表批次验证，再运行其余批次。

通用适配器读取 TIFF 等图像及显式的 `frame_metadata.csv`／`measurement_frames.csv`；DESY 适配器另解析 Delun／相机目录、CBF 头和 FIO 日志。没有证据支持的跨源映射保持缺失。载荷时间列和单位由对齐参数明确指定，不能根据文件行数推断时间。

本轮失败经验形成以下检查顺序：

| 现象 | 首先核对 | 保留的处理结果 |
| --- | --- | --- |
| 取点可能落在夹具 | 首、中、末帧材料自由段及排除区 | 未审核阻断，修改后重新审核 |
| 单向纹理或周期纹理 | 方向性、相关峰歧义和前后向误差 | 失败原因与轨迹，不降低阈值 |
| 同号重复图像 | 原始编号、内容 SHA、scan 命名空间 | 相同副本与内容冲突分开记录 |
| 相机与分析帧数不同 | 实际时间记录和显式帧映射 | 不按排序行号配对 |
| 无 DIC 或无可靠面积 | 原始图像是否存在、尺寸来源是否确认 | 保留 frame／时间／载荷；缺失值不填零 |
| 载荷缺口或时钟不明 | 支撑点间隔、无效记录和时区 | 不跨缺口、不外推，保留状态 |
| 修改 ROI 后应变不同 | 同一参考下的重叠有效帧与参数变化 | 独立重试与敏感性记录，不解释为独立重复实验 |
| 网络盘写入停滞 | 本地完整包、目标锁和发布回执 | 保留本地包，失败版本不成为 CURRENT |

## 复用已有科研成果

`import-keystone` 读取已验证版本的身份、逐帧表和来源索引，保留 acquisition ID、原始数值、缺失语义及附加质量列。只复制小型元数据与接受表，不复制原始图像，不改写源 CURRENT.json。导入结果标为 IMPORTED_ACCEPTED，并保留其原生产者证据，不能声称由新代码重新计算。

不同阶段分别绑定输入、配置和代码指纹：修改导出位置不应触发重新追踪；取点或原始图像改变会使原审核和相应跟踪缓存失效。重新建议或重试创建候选证据，不会自动放宽质量要求，也不会替换导入的接受值。

## 科学边界

- ROI 坐标为参考图像像素中的 [x,y,width,height]，不是 [x0,y0,x1,y1]。端点窗口须在已审核试样自由段内。
- 引伸计采用固定参考和二维端点距离。工程应变为 L/L0−1，真应变为 ln(L/L0)；不逐循环归零。零值只相对于参考帧。
- 默认建议五条引伸计；有效条数不足五条如实保留。至少三条通过质量检查才计算均值与样本标准差。标准差表示空间离散，不代表独立重复实验的测量不确定度。
- 二维 DIC 输出单独保存，不能把场应变、单条引伸计和多条引伸计均值自动视为同一量；单相机只提供平面表观响应。
- frame 是分析轴，原始图号和 scan 命名空间另存。图像缺帧不能用排序行号填补；不同源的同号图像不能自动配对。
- 绝对记录时间与推算时间分开。文件修改时间不作为采集时间；一秒连续拍摄、时区和起始锚点必须有明确配置或来源，不能默认套用。
- 载荷单位 N、应力 MPa、应变无量纲、面积 mm²。新应力只用已确认面积。候选面积不进入正式应力；导入的既有应力遇到冲突时保持原值并标记。
- 插值只在有效支撑范围和配置的最大间隔内进行，保留支撑点、权重与状态；不外推、不跨无效记录、不用插值掩盖失配。

## 输出与恢复

项目保存审核、阶段状态及相对 artifact 路径。导出包含 catalog、sample.json、frames.csv、frames.jsonl、sources.json、Origin TXT、校验和与验证记录。CSV 应力缺失为字面 null，应变缺失为空；JSON 数值缺失统一为 null，禁止 NaN/Infinity。

先在本地完成版本和压缩包，再按需发布。目标写入由单一发布者串行完成，逐文件校验；完整验证后才更新 CURRENT.json。失败时保留完整本地包和失败记录，不把部分版本标为当前。

## 验证的含义

合成平移、转动和伸长用来回归算法行为；文件校验用来证明完整性。两者都不是实验测量准确度或离面运动误差的校准。真实科研包的本地回归只证明被接受的数据在导入、对齐和导出中没有无意改变。
