# StrainTrace Capture

Capture runs the cameras and saves images. Analysis opens an existing image folder or reads a Capture experiment in a separate process. The two workbenches can run independently or together.

## Install and start

| Workbench | Installed command | Windows portable | Source checkout |
| --- | --- | --- | --- |
| Capture desktop | `straintrace-capture-gui` | `StrainTrace-Capture.exe` | `start_Capture.bat` or `python -m straintrace_capture.gui` |
| Capture CLI | `straintrace-capture` | `StrainTrace-Capture-cli.exe` | `python -m straintrace_capture` |
| Analysis desktop | `straintrace-gui` | `ezDIC.exe` | `start_ezDIC.bat` |
| Analysis CLI | `straintrace` | `ezDIC-cli.exe` | `python -m ezdic_cli` |

Windows 源码入口共用项目的 `.venv`。在 PATH 或 Python 启动器能找到 Python 3.11 至 3.13 时，首次启动会准备环境并安装 `requirements.txt`。若旧环境的解释器已经失效，启动脚本会把它保存在同目录的 `.venv.backup-*` 中，再创建可用环境。启动日志写入 `%LOCALAPPDATA%\ezDIC\state`，可用 `EZDIC_STATE_DIR` 指定其他日志目录。

Install the source package with `python -m pip install .`. Optional extras are `".[capture-uvc]"` for device-path enumeration, `".[capture-pylon]"` for Basler and `".[capture-gentl]"` for GenTL.

### Windows 工业相机便携版

完整解压 `ezDIC_Windows_x64_Industrial`，保留 `_internal` 后打开 `StrainTrace-Capture.exe`。这个版本自带 pypylon、Harvesters 和 GenICam 组件，可以直接使用模拟、普通 USB 视频设备和工业相机接口。

- Basler 相机接上后点**刷新**。按设备接口安装所需的 [Basler 相机驱动](https://docs.baslerweb.com/pypylon-installation-and-environment-setup)。
- GenTL 相机先安装厂商的 64 位驱动或 SDK。已注册的接口会随**刷新**自动搜索。若**驱动状态**提示缺少接口文件，点**选择厂商 .cti**，从厂商原安装目录选取相机对应的文件并连接预览。[Harvesters 安装说明](https://github.com/genicam/harvesters/blob/master/docs/INSTALL.rst)
- 命令行可使用 `discover --cti PATH` 检查接口。采集计划使用 `cti_files` 保存所用路径。

Basler 的**像素格式**下拉项包括相机报告且 SDK 支持的 10 位和 12 位单色及 Bayer 打包格式，如 `Mono12p`、`Mono12Packed` 和 `BayerRG12p`。Capture 解包后用 16 位无压缩 TIFF 保存，台账记录相机报告的格式名和实际有效位数。Bayer TIFF 保留传感器排列，采前按解包后的像素量估算存储空间。悬停于格式选项可查看有效位数和每个样本占用的字节数。 [Basler 像素格式](https://docs.baslerweb.com/pylonapi/net/T_Basler_Pylon_PixelType)

GenTL 通过驱动报告的像素格式、图像偏移和填充读取 10 位和 12 位打包灰度及 Bayer 图像。预览报**无法确认打包图像的行边界**时，按悬停详情给出的像素倍数调整采集宽度，或选用相同位深的非打包格式，再连接预览并试采。 [GenTL 缓冲区信息](https://www.emva.org/wp-content/uploads/GenICam_GenTL_1_6.pdf) · [PFNC 打包规则](https://www.emva.org/wp-content/uploads/GenICam_PFNC_2_4.pdf)

**GenTL 主图像**默认为 `auto`。只有一个可读取的二维图像时会直接预览。连接后，在画面下方的**主图像**列表中查看各路图像的尺寸、像素格式和偏移。选择一路并核对新画面。收到匹配的图像后，所选编号会写入当前计划。多相机预览时，单击画面可以换到另一台相机。

也可以在**相机参数**或 JSON 计划的 `gentl_image_part` 中手动填写编号。例如 `2/16/0/Mono12p` 依次对应源编号、横向偏移、纵向偏移和像素格式。`-` 表示相机未报告该项。同一源只有一个可用二维图像时也可填源编号 `2`。采前估算使用预览确认的尺寸，复查页显示每张保存图像的部件编号。正式采集期间，部件缺失或图像来源改变会报告错误。 [GenTL 多部件定义](https://www.emva.org/wp-content/uploads/GenICam_GenTL_1_6.pdf)

收到多路二维图像时，可在预览下方勾选**保存全部二维部件**，也可在该相机的 JSON 设置中加入 `"gentl_save_all_2d": true`。同一缓冲区中的各个可解码 PFNC 二维图像分别保存为无压缩 TIFF，共用一条帧记录和触发关联。采前检查和试采会按所有部件估算数据量。进入**复查与分析**，在**本帧图像**选定一路后，可对它做实时分析、离线分析或镜头标定。GenTL 允许各部分来自不同传感器，跨部件测量需要单独核对空间配准和曝光时序。 [GenTL 多部件定义](https://www.emva.org/wp-content/uploads/GenICam_GenTL_1_6.pdf)

开发者可运行 `.\build_release.ps1 -Industrial` 构建这一版本。发布脚本会从已构建的程序运行 Basler CamEmu 与 GenTL Viky 混合采集并校验 TIFF。标准构建生成包含模拟和普通 USB 视频接口的便携版。

## 桌面采集流程

采集工作台默认使用简体中文。标题旁显示当前是模拟练习、实验相机或实验复查。同时选中模拟和实验相机时，也会明确显示。顶部提示条会根据当前状态推荐下一步，例如连接预览、检查计划、打开离线分析或检查中断。右上角的**新手指南**按流程提供说明，可直接定位到对应控件。需要开始采集时，使用右下角的开始按钮。

在计划页编辑实验名称、输出目录和存储模式。试采、正式采集和复查时，页顶显示对应实验的实际目录。悬停或按 F1 可查看完整路径，也可选中路径后按 Ctrl+C 复制。点右下角的**返回采集计划**可接着编辑原计划。回到复查页后，可继续查看已打开的图像。

连续采集多组试样时，可以沿用当前相机和阶段设置。返回计划后，如果输出路径已被目录、文件或目录联接占用，页顶会提示更换。点**使用新路径**可填入同级建议，例如 `试样 A03-run-02`。悬停或按 F1 可核对建议的完整路径。修改实验名称后，再点**开始采集**创建目录。采前检查遇到路径占用时，也可以在相应事项下点**使用新路径并检查**。

窄窗口把设备移入右侧的**相机**标签，旁边可切换**计划、画质、复查**。宽窗口准备采集时，相机列表位于左侧。复查时，画面可使用这部分空间。需要选相机时，可用顶部的**定位到相机列表**打开列表并将焦点移入，再用鼠标或方向键选择。短窗口可以滚动查看设置，按 Tab 聚焦控件时会自动滚动到相应位置。选中较长的阶段后，可在阶段列表下方查看完整参数。

首次使用且发现实验相机时，可点顶部的**选择实验相机**，按型号、序列号和接口勾选设备，再点**连接预览**。只有一台可选设备时会预先勾选，确认后才连接。多台相机可逐一勾选。取消时保留之前的设备选择。

未发现实验相机时，可从顶部点**打开模拟练习**。也可随时通过**新手指南**启动独立窗口。练习窗口自动显示内置模拟散斑，可以用同样的工作台检查计划、保存图像、复查和分析。默认先保存一张参考图，再以每秒 6 张保存 12 张实验图，图像存入 `文档/StrainTrace Capture/模拟练习` 下的独立目录。练习窗口使用独立的最近实验列表。源码或 Windows 便携版也可用 `--practice` 打开这个窗口。

鼠标停在按钮、输入框、选项或表格上可查看说明。按钮变灰时可查看需要先完成的操作，说明会随当前状态更新。按 Tab 聚焦后按 F1 可查看焦点控件的说明。在主界面或对话框中，用 Shift+F1 可固定鼠标所指控件的说明，鼠标移开后仍可阅读。展开下拉框后，悬停或用方向键比较各项。按 Esc 收起说明。采前检查、试采和台账校验的报告可用**复制报告**整份复制。

**检查结果**把阻塞项、需复核的事项和一般提示按顺序列出。选中一条可查看涉及的相机、阶段和数值。可从有操作按钮的事项进入对应设置，保存后会重新检查。需要确认提醒时，点**仍按当前设置开始**才会启动采集。计划、相机连接或输出位置变化后，旧报告中的设置和开始按钮会禁用。切换到**完整报告**可核对空间估算、相机回读和试采对照。

在**采集模板**中按任务选择方案，可以先改定时频率、张数、最长时长或事件前后的张数。阶段表显示执行顺序和等待确认的阶段。打开窗口时已有有效预览的相机用预览图像估算原始像素量，其余相机用已知的设置估算。硬件触发模板需要填写实际接线的输入。确认后点**应用并替换阶段**，再检查计划和试采。

1. 接上实验相机后点**刷新**，再用**选择实验相机**连接预览。也可在设备列表中选中相机，按住 Ctrl 可多选。点**相机参数**可查看和调整设备支持的曝光、增益、帧率和传感器区域。
2. 用**查看图像质量**检查光照、曝光和清晰度。按住 Shift 在图像上拖出检查框，或点**输入区域**填写坐标和尺寸。亮度直方图、近黑、近饱和、对焦响应和局部纹理都读取框内数据。相机参数里的传感器区域决定实际保存的像素范围。
3. 选择一个新的输出目录，在**采集计划**选择模板或编辑各阶段。应变实验通常先采加载前的参考帧，再记录实验帧。用**检查计划**查看触发条件、缓冲限制和磁盘空间。计划或输出位置修改后，之前的报告会标记为已修改。选中一个阶段后点**试采**，用当前相机和写入设置验证实际接收帧率、图像格式和缓冲用量。试采的 TIFF 和台账保存在正式输出位置旁的新目录。
4. 点**开始采集**。手动或事件阶段可用**触发一次**。事件阶段会显示各相机都已完成的缓存轮数、触发请求入队状态和事件后收图进度。提前触发时，台账会记录事件前窗口不足。硬件触发阶段在相机启动后等待设备送图，并显示主机已收到的张数。停止并保存后自动打开**复查与分析**。单击相机画面可切换设备。向下滚动复查页可查看台账校验、续采和镜头标定。
5. **实时分析**可在独立窗口跟踪已保存的图像。在参考图上按住 Shift 绘制两个标距端点或一个全场区域，再点**开始跟踪**。暂停实时分析时，采集继续保存图像，**待分析**会随台账更新。**离线分析**可逐帧计算并导出结果。有多张参考图时，可在离线分析打开前按图像序号和采集阶段选择。
6. 如进程异常退出，重新打开实验并点**检查中断**。先看已登记帧数、可恢复帧和待复查原因。核对后可点**恢复台账**，然后选择续采起点。

### 选择实时计算顺序

在实时应变曲线上方选择**优先看最新**或**按序逐帧**。优先看最新适合现场观察。有多张待分析图像时会先计算最新图像，省略的帧计入**实时跳过**，原图仍可复查或离线分析。按序逐帧从当前进度开始逐张计算。采集结束后可继续算完**待分析**里的图像。

跟踪时可按已配置的测量切换**应变–时间**、**载荷–时间**和**载荷–应变**。载荷–应变图只绘制同一帧具有有效载荷和应变的点，并按采集顺序连接。时间视图在图底用短线标记有原图的缺测帧。缺测及实时跳过的区间会断开曲线。

悬停查看帧号、收图时间和测量质量。点击选中后可点**核对帧**读取原图，也可双击，或聚焦曲线后用方向键和回车操作。核对窗口按该点的实验、相机、图像部件和 SHA-256 读取原图。曲线显示最近 500 张分析结果，完整逐帧记录仍可导出。

在采集工作台的**复查与分析 → 历史曲线**可重开整份逐帧记录。实时分析窗口也有同名入口。默认打开最新一份，可用**选择记录**查看早期的跟踪。每段最多显示 500 张，用**上一段**、**下一段**或帧序号定位。**下一处缺测**按当前曲线查找，能够跨段跳转。全场质量视图显示有效应变点比例，标出需要复查的帧。把鼠标停在点上，可核对已保存的测量质量和原图。

历史窗口读取打开时已有的完整记录。若跟踪仍在写入，可点**重新读取**查看新增部分。帧号定位针对本轮图像，实时跳过的图像可在采集复查里按原帧号查找。

暂停期间，采集和写入继续进行，底部会更新**待分析**。两种方式都可以在跟踪或暂停时切换，从当前进度继续。重置会在当前一次计算结束后恢复测量区设置。

#### 从历史曲线导出表格

点**导出表格**，默认保存已读取的整份记录。也可选**当前段**，或在**指定帧号**中输入单个序号 `522` 或连续范围 `510-530`。三种范围均保留原参考图。表格包含范围内已有的实验帧和所有已记录的测量量，每个标距单独占一行。已分析和实时跳过的累计张数取自原记录。若需要刚写入的结果，先在历史窗口点**重新读取**。

默认使用逐帧记录中的载荷与位移数值。勾选**补齐缺失的载荷与位移**可使用同一轮试验的更新表。表格保留已匹配的数值，并注明后到采样所补齐的值和对应依据。选择**保存 CSV**设置文件名与位置，完成后可直接打开保存目录。

```powershell
straintrace-capture export-live-results "E:/runs/demo/live-results/run.jsonl" --frame-range 510-530 --output "E:/reports/frames-510-530.csv"
```

#### 补算实时跳过的图像

在**历史曲线**中打开对应记录，点**按序重算**。直接沿用原参考图、图像部件、标距和全场测量区。程序按相机序号计算开始时已登记在台账中的实验图，包含实时跳过的帧。若沿用的是上一轮的参考图，则从本轮第一张实验图开始。采集可继续进行，新入账的图像可在下一次重算时纳入。

已设置载荷对齐时，默认沿用原载荷表和时间设置。原表移动或已补齐采样时，可选同一轮的更新表。程序核对早期用过的采样，并在本次重算中固定使用核对通过的载荷数据。取消勾选可只重算图像测量。完成后自动打开新曲线，原逐帧记录仍可在**选择记录**中打开。取消或出错时，未完成的结果不会列入历史曲线。

```powershell
straintrace-capture replay-live-results "E:/runs/demo" "E:/runs/demo/live-results/run.jsonl"
```

命令支持 `--load-table` 和 `--images-only`，输出新记录路径、本次计算范围和来源校验信息。可用 `export-live-results` 将新记录导出为 CSV。

### 恢复上次采集计划

修改后的有效计划会自动保存为本机草稿。重新打开 Capture 后，点顶部的**恢复上次计划**，找回相机设置、采集阶段、当前所选阶段和保存位置。恢复完成后，可继续检查计划或连接预览。需要接收外部软件触发命令时，请为本次采集勾选相应选项。

恢复时会按实验编号重新读取草稿关联的试采，保留其抽查或全查范围，并由采前检查再次核对输出卷与当前设备。找不到某个阶段的试采时，可在**最近实验**中定位移动后的目录，再恢复计划。草稿留在本机，**保存计划**可另行导出 JSON。

### 检查计划中的相机连接

相机列表的**查找**列显示上次刷新是否找到这台设备。悬停或按 F1 可以查看完整设备编号。预览尚未开启时，桌面的**检查计划**、**试采**和**开始采集**会按所选编号打开并关闭实验相机，读取计划需要的参数和触发信息。已开启预览时，检查使用当前预览的设备证据。

更换相机后可直接查看新设备的预览。旧计划为原相机逐台记录了物理输入或脉冲计数时，点**核对阶段**打开对应设置。在预览仍连接时可以读取当前相机支持的端口。核对实际接线及计数后应用该阶段，再检查计划或试采。

如果连接检查失败，采前报告会标出相机和具体原因。接回原设备或关闭占用相机的程序后，直接点**刷新并检查**。采集计划、所选相机和保存路径会保留。检查通过后，由操作者决定何时开始试采或正式采集。

### 恢复单台相机的预览

一台相机停止送图后，异常画面会显示释放旧连接、等待重连或重连失败。悬停或按 F1 可看原因。修复连接后，选中异常画面并点**重连相机**，其他相机继续送图。若此时选中的是正常画面，「下一步」会显示准备重连的相机名称。

已有预览的设备如果按序列号或系统设备路径识别，发生连接中断或送图超时时，Capture 会尝试自动恢复。自动尝试的等待时间依次为 1、2 和 4 秒。设备已连续稳定送图至少 10 秒后，下一次中断可重新使用这三次尝试。设备若只按视频输入序号识别，由操作者发起重连，并核对恢复后的画面。

恢复时重新应用原计划的相机参数，核对设备身份、已回读的参数和新图像的尺寸、格式及部件。所选相机全部恢复画面后，可重新检查计划或开始采集。连接发生变化时，旧采前结果需要重新检查。正式采集中断后，可在**复查与分析 → 检查中断**核对已登记文件并准备续采。

### 保存一张预览原图

连接预览后，单击要保存的相机画面，再点预览下方的**保存预览原图**。选择新的 `.tif` 或 `.tiff` 文件名。即使选路径时相机继续送图，保存的也是按下按钮时显示的那一帧。按钮悬停和 F1 会显示所选相机、画幅和有效位深。

TIFF 保存完整画幅和原始像素，并在 `ImageDescription` 保存相机身份、像素格式、有效位深、主机收图 UTC 时间和可用的部件信息。伪彩、辅助线、畸变校正和检查框只影响预览。保存后可在窗口底部查看文件名，悬停或按 F1 查看完整路径。同名文件已存在时，换一个文件名即可。需要记录一组数据、阶段或触发关系时，可从采集计划开始。

点**原图对照**可打开刚保存的 TIFF。左图显示保存时的相机画面，右图可取同一相机当前显示的预览帧。调整照明、曝光或试样后，点**取相机当前帧**更新右图。也可通过**打开左图**和**打开右图**离线对照两张已保存的预览 TIFF。将鼠标停在图像下方的来源和统计上，或聚焦后按 F1，可查看完整路径、主机收图时间和指标含义。

两张图的相机身份、像素格式、画幅、主图部件及已知传感器范围相符时，按 Shift 在任一图框选，两边用相同像素坐标计算亮度中位数、近黑和近饱和比例。早期 TIFF 缺少传感器范围读数时，可查看两边各自的全图统计。新保存的 TIFF 会记录可读到的传感器偏移、合并和抽取参数。

### 一次检查多台相机的画质

连接多台相机并收到预览后，在**图像质量**点**检查各相机**。每台读取 5 张新画面，显示近黑和近饱和的最大比例及触发提醒的张数。当一张画面里至少 20% 的像素落在最低或最高 1% 的码值范围内，对应相机会出现提醒。可悬停结果或聚焦后按 F1 查看采样时间、范围和建议。

有检查框时，程序统计框内亮度和纹理。其余相机使用整幅画面。相机保存的画幅由相机读取设置决定。点**查看画面**可定位到所选相机。采前报告会列出仍匹配当前连接、设置和检查框的结果，并可从提醒直接打开对应画面。调整照明或检查框后，点**重新检查**读取新画面。 [Basler 相机画幅说明](https://docs.baslerweb.com/image-roi)

### 在同一区域检查曝光和对焦

在**图像质量**选中需要看清的相机画面，框住试样或散斑。直方图按图像亮度统计，近饱和比例按最高 1% 码值范围统计。彩色图像中任一颜色通道进入这个范围就会计入。Bayer 图像的曝光统计读取原始感光点，对焦和纹理读取同一组绿色感光点。

相机提供以微秒表示的可读写曝光时间和范围时，可点**曝光建议**。固定光源和试样，关闭相机的自动曝光和自动增益，然后点**测量**。程序读取五张新原图，比较亮部第 99 百分位与满量程的比例，以及近饱和像素占比。彩色像素取最亮的颜色通道。画面波动过大或亮部也接近全黑时，请先核对光照和检查框。

建议值按相机当前允许的范围和步长取值，并受已设定的最短帧周期限制。运动试样可填写更短的**最大曝光**以控制拖影。点**试设并复测**后，程序先核对原画面的亮度，再试设所选相机并读取五张新画面。近饱和减少或亮部获得更合适的余量时，采用该曝光到当前采集计划。复测失败时，程序核对恢复后的参数和画面。可继续查看原图细节，再用试采核对帧率和拖影。 [Basler 曝光时间说明](https://docs.baslerweb.com/exposure-time) · [Basler 实际帧率影响因素](https://docs.baslerweb.com/resulting-acquisition-frame-rate)

固定相机、试样、照明、曝光和增益，点**开始对焦比较**，缓慢转动镜头的对焦环。当前值取最近三张新画面的中位数，同时保留本轮最高值。对照数值并查看原图，确认细节清楚后点**结束对焦比较**。切换相机、改变检查框或修改相机参数后可重新比较。若相机回读为自动曝光或自动增益，先在相机参数中关闭相应的自动调节。

**清除区域**后可回到全图统计。检查框超过 100 万像素时仍可看曝光和对焦数据，缩小后可查看详细纹理指标。

### 逐台监看收图和保存

开始后，「采集计划」会切到**采集监看**。相机列表每行显示本阶段主机收到和已登记保存的帧数。「待存」按本次采集统计，包括已进入写入队列且尚未登记的帧，也包括正在写入的帧。事件前滚动缓存仍占用字节缓冲，可在阶段状态查看缓存轮数。一帧可包含同一次接收中的多张 TIFF。

已配置共享脉冲与各台相机计数器锚点的硬件阶段，可以打开**脉冲监看**。选中一个编号可看每台相机收图和登记的情况。配置了等待输出回读时，首帧前还能看到相机报告的就绪状态。某台相机已经收到更大的关联编号时，界面会提示前一组尚未收齐。悬停或按 **F1** 可查本组收到的帧数、起始计数器和重复编号。窗口保留起始编号及后续观测中最大的 24 个编号。采集结束后，**校验图像和台账**可查看最后一个带锚点阶段的收图与登记快照。物理漏拍和曝光同步可用独立 DAQ 记录核实。

硬件阶段可从顶部点**查看触发状态**进入采集监看。选中一台相机，可核对它的计划触发输入和首帧收图情况。启用等待输出监测后，行内说明会显示等待输出线路及相机回读。悬停或按 **F1** 可查看详情，也可在尚未收到首帧的相机画面上直接查看。若已发出物理触发但只有部分相机送图，可据此核对其余相机的接线。物理脉冲是否到达可用独立记录确认。

选中相机行可切换画面，并查看距上次收图的秒数和本阶段主机接收帧率。后者由本阶段首尾两帧的主机收图时间计算。若本阶段尚未收图，上一阶段保留的最后一帧会标为**上阶段图像**。悬停在表格或按 F1 可查看当前状态和具体异常计数。

外部触发阶段还没有相机送图时，列表显示**等触发**。若一台相机至少 1.5 秒没有新图、其他相机近期有图，会标出**无新图**。可检查这台相机的输入接线和外部脉冲。漏拍与同步仍可在采后用独立触发与曝光记录核对。

点**写入趋势**可查看字节缓冲、待写批次和近期速率。入队和登记速率都按原始像素字节统计。字节缓冲只统计仍留在内存中的原始像素，包括事件前缓存。待写批次统计尚未交给写入线程的批次。原图写入文件后，台账登记完成前仍计入采集监看中的待存帧数。

连续、定时或硬件触发阶段可区分短时积压、持续落后和积压回落。连续两个约 2–3 秒的区间均有增长并满足提醒条件时，按观察到的增速估算最先触及的上限。手动和事件阶段可查看实际占用和近上限提醒。若需提前结束，可点**停止并保存**。完成后，**校验图像和台账**会列出各阶段出现的写入提醒及可用的速率依据。

### 正式采集的画质提醒

桌面默认开启**画质提醒**，可在采集计划中取消勾选。开始后从**采集监看 → 画质抽查**查看各相机的抽查帧号、近黑和近饱和像素占比，以及相对于本阶段参照的清晰度响应。出现持续异常时，顶部也会提示，可直接打开抽查表。

预览时按住 Shift 在相机原图上框住试样，再点**用于采集抽查**。检查框按相机保存到采集计划和草稿，试采和正式采集都可使用。恢复计划后重新连接预览，画幅匹配的相机会显示保存的检查框。可从同一位置点**恢复全图抽查**。检查框用于画质统计，TIFF 保存相机传来的完整画幅。采前报告列出每台已设置相机的范围和已知差异。采集中如原图尺寸、格式、主图部件或可核对的传感器画幅设置不匹配，程序改用全图，并在监看和时间线注明原因。

抽查轮流读取各相机最近一张已入队的主图。近黑和近饱和按有效码值的最低、最高 1% 统计，任一比例达到 20% 时开始判断。实验阶段用同一相机、同一图像布局下最初三张曝光可比较的样本建立清晰度参照。亮度可比较时，清晰度响应降到参照的 45% 或更低会计入异常样本。连续三次抽查达到条件时出现提醒。清晰度响应也受拖影、试样纹理和照明影响，可到**画质**框选关心的区域复查。

后台每 0.20 秒最多抽查一台相机的一帧。待写字节缓冲或批次队列达到一半时暂缓抽查。提醒期间按采集计划继续保存，统计范围为实际抽查的图像。**采集时间线**保留提醒和解除时的相机及帧号。点**定位抽查帧**，可按相机、阶段、序号和收图时刻查找对应原图。

命令行可用 `run --watch-quality` 开启。计划的 `quality_regions` 按相机记录原图像素坐标 `[x, y, 宽, 高]` 和对应的图像布局。实时状态和完成后的实验摘要包含 `image_quality_watch`，记录抽查次数、暂缓次数以及各相机的最近统计范围和结果。

### 暂停与继续当前阶段

正式采集的定时或手动触发阶段，可点底部的**暂停采集**。当前多相机拍摄轮次结束后暂停，已进入队列的图像继续保存。界面变为**采集已暂停**时，阶段的时长计数和后续拍摄请求都已暂停。仍可按 **F8** 记录观察，也可点**停止并保存**结束采集。

点**继续采集**会在同一个实验、同一个阶段恢复剩余请求和原设定的拍摄间隔。正在等待执行的手动请求会先完成，暂停期间可以在界面查看暂停前最后收到的图像。使用主机选帧的相机可继续向主机传输，恢复后按新请求选取图像。连续、硬件触发和事件缓存阶段由各自的收图方式控制。

**采集时间线**显示暂停开始、收到继续请求和暂停中结束的时刻。黄线标出有暂停记录的时段，阶段结束行的悬停说明显示累计暂停时长。定时漏拍的计划时刻按暂停前后各自的时间基准计算。

启用外部命令后，脚本可查询状态并对当前阶段发出请求。等待 `phase_pause.state` 为 `paused` 后，将其中的 `pause_id` 用于恢复同一次暂停。

```powershell
straintrace-capture pause-phase "E:/runs/test" --phase 2
$live = straintrace-capture status "E:/runs/test" --live | ConvertFrom-Json
$pause = $live.status.phase_pause
if ($pause.state -eq "paused") {
    straintrace-capture resume-phase "E:/runs/test" --phase 2 --pause-id $pause.pause_id
}
```

### 重新打开最近的实验

点顶部的**最近实验**，双击记录即可进入复查页。列表最多保留 12 次最近使用的实验。新采集创建台账后即会登记。选中记录可查看完整路径，悬停或按 F1 可查看用法。

如果目录改名或移到另一块磁盘，在列表中选中原实验，点**定位已移动的实验**，再选新目录。Capture 会核对台账中的实验标识，通过后更新位置并打开原图。首次复查、从其他电脑复制来的数据和较早的实验可通过**打开实验**直接选择总目录。

### 用完整计划准备复拍

完成一组正式采集后，在**复查与分析**点**准备复拍**。核对来源、各阶段的拍摄方式和新输出位置，可填写下一组的试样名称。**载入并检查**会载入来源台账的相机、阶段、存储设置和已核验的归档标定，重新搜索设备并打开采前检查。确认准备好后，再点工作台的开始按钮。

新实验有独立目录和标识。原计划包含参考帧时会按阶段重新拍摄。来源实验若使用了硬件脉冲关联，请在本轮核实实际首个共享脉冲，再填写各相机的新计数器锚点。完成后可在**关联实验**按来源标识切换查看。

脚本可用 `straintrace-capture prepare-repeat 实验目录 --name 新实验名称 --output 新目录` 输出计划 JSON 并检查目录。可将 JSON 导入工作台或用于正式采集。

### 核对采集结果

采集结束或重新打开实验时，**复查与分析**显示当前实验名称、台账登记的帧数、TIFF 张数和本次文件校验状态。相机一次收图可能含多个部件，因此一帧可对应多张 TIFF。悬停或聚焦后按 F1，可查看各相机的计数和采集期间已记录的异常。

顶部会根据当前证据推荐操作。采集失败或中断且帧写入记录有待核对时，优先提示**检查中断**，其中会核对遗留 TIFF 是否可以补登记。点**查看异常记录**可直接打开全部相机的异常列表。**校验图像和台账**会读取存档中的原图及归档标定，检查文件哈希和台账中的触发关联。出现问题时可从**查看校验报告**打开本次报告。如果图像读取失败，悬停可查看原因。界面会将此前通过的文件校验改为待校验。物理曝光同步需要独立时序证据。

### 检查正式采集的原图画质

在**复查与分析 → 数据检查与恢复**点**检查原图画质**，选择相机和阶段。打开时先均匀抽查主图像，包含首末帧，每次最多 96 帧并参考 64 MiB 的原图数据量。点**检查全部**可逐张核对该阶段。点**停止**可保留已完成的结果，窗口会注明检查范围和已核对帧数。

切换到**整场检查**会按相机和阶段抽查整场实验。汇总列出各组已查和已登记帧数、通过核对的帧数、提醒和首条提醒帧。还可点**逐张查整场**。中途停止后，已查结果和未检查的组都会保留在表里。选中一行点**查看该组原图**，即可用已有结果查看帧和原始 TIFF。**复制汇总**会带上实验标识和所有组的覆盖情况。

在**整场检查**点**导出报告**，可把当前检查结果保存为 ZIP，位置选在原实验目录之外。压缩包内的 `coverage.csv` 列出各组的覆盖和状态，`frames.csv` 记录已查各帧的原图相对路径、台账 SHA-256、主机收图 UTC、实际检查框、像素采样步长和提醒。三个像素比例列使用 0 到 1。未通过核对的帧保留在逐帧表，相应画质数值留空。`report.json` 包含实验标识、检查方式、阈值及各组归档检查框。中途停止后导出的报告会保留未检查的组。

自动化可运行 `straintrace-capture export-quality-report <实验目录> --output <新报告.zip>`。加 `--all-frames` 改为逐张检查。命令返回报告位置和覆盖统计，出现组检查失败或 TIFF 未通过核对时返回退出码 4，并保存已取得的记录。

原计划保存了检查框时，默认检查框内像素。实际画幅、像素格式、主图部件或已登记的传感器范围变化时，该帧改查全图并显示原因。取消勾选**使用计划检查框**可抽查全图。近黑和近饱和分别依据最低与最高 1% 的码值判断，比例达到 20% 时产生提醒。彩色图像任一颜色通道达到近饱和阈值即计入。

勾选**只看提醒**可定位异常和无法核验的 TIFF。选择一行可查看核验后的原图、实际检查框和收图时间，悬停或按 F1 查看提醒原因。点**在复查页打开**可定位到该帧并继续检查相邻图像。画质检查用于筛查图像，对照应变结果时还需核对实际相关计算。

点**对照当前预览**，左图载入选中帧经核验的原始 TIFF，右图可取同一台相机的当前预览。两图的相机身份、像素布局和传感器范围可核对且相符时，自动共用本帧检查框。画幅或传感器范围不相符时，两图各自统计全图并显示原因。相机身份无法核对时，可另行打开右侧的预览 TIFF。悬停左图来源或按 F1 可查实验、阶段、帧号和 SHA-256。

还未连接时，点**定位相机**可到主窗口找到设备。已有该相机的预览时，此按钮打开对应画质页。核对通过的检查框可带入画质页用于本次曝光和照明检查。调整后，从预览下方的**原图对照**返回，再点**取相机当前帧**复核。右侧指标读取所取那一帧的原始像素。

### 从采集时间线定位异常

在**复查与分析 → 数据检查与恢复**点**采集时间线**，将**事件类型**设为**仅看异常**。可继续按相机和阶段缩小范围。绿色标出各阶段，灰色标出人工确认等待，蓝柱按主机收图时间统计已保存帧，橙点标出可定位的异常。点蓝柱可查该时段的原图。聚焦时间图后也可用方向键选时段并按 Enter。悬停或按 F1 可查看时间范围、帧数和图例。

选中事件，图中虚线标出该行的时刻。悬停可读到纳秒和时间来源，用 Ctrl+C 可复制带时区的时间。定时漏拍的计划时刻按阶段起点换算。旧台账只保存登记时间的漏拍保留在列表中，时间图按可定位的记录绘制。需要核对曝光时刻时，可使用**核对时序**。

选中一行后，列表下方会提示可执行的操作。点**查附近原图**可按相机、阶段和时间查询。写入错误记录含待写帧收图时间时，可从该时间附近找已保存的原图。选中**触发组图像不齐**时，双击或按 Enter 可查看该组原图，缺帧相机会单独标出。事件窗口收图不足时，可按该次触发查找已保存的前后原图。未接收的触发请求按阶段汇总。相机只提供累计计数时，可悬停在列表上方的统计文字查看全实验计数。

```powershell
straintrace-capture timeline "E:/runs/test" --camera sim:0 --phase 2 --incidents-only
```

### 记录现场标记并查找前后原图

采集中看到滑移、裂纹或其他变化时，点**标记事件**，或在采集窗口按 **F8**。需要备注可先在**采集监看**填写**标记说明**。点击时记录主机时刻，台账写入成功后会显示**标记已保存**。采集按当前阶段继续执行。

复查时打开**采集时间线**，将**事件类型**设为**仅看实验标记**。紫色菱形显示有标记的时间段。选中标记后点**查看前后原图**，可逐台查看标记时刻及之前最近的一张，以及标记之后最近的一张。负值表示先收图，正值表示标记后收图。选中有序号的一行可打开校验过的 TIFF。记录到达主机的时间差使用同一单调时钟。要核对实际曝光时序，需使用独立时序证据。 [Python 单调时钟说明](https://docs.python.org/3/library/time.html#time.perf_counter_ns)

运行时已启用本机命令通道的实验可用以下命令记录和复查。第一条返回已排队的标记 ID，后两条读取已写入台账的记录。

~~~text
straintrace-capture mark 实验目录 --label "开始滑移"
straintrace-capture timeline 实验目录 --markers-only
straintrace-capture marker-context 实验目录 MARKER_ID
~~~

### 查找和打开特定图像

在**复查与分析**点击**查找图像**。先选相机，可再选采集阶段和图像用途。序号框填 `42` 查一张，填 `40-80` 查一个范围。序号在每台相机内分别登记。结果支持按台账登记顺序翻页，采集中重新点**查询**即可纳入新登记的图像。

勾选**按收图时间**后，可输入带时区的起止时间，例如 `2026-11-25T09:30:00.123456789Z`。这里使用主机收到图像的时间。曝光时间与跨设备时钟对齐可在**核对时序**或时间戳导出中查看。悬停在结果上会显示完整纳秒时间，在列表中按 `Ctrl+C` 可复制所选行的收图时间。

双击一行或点击**打开原图**，程序核对实验身份、帧记录和所选 TIFF 的校验值后，切到相应相机显示图像。点**查看触发组**可并排复查同一触发记录对应的各台相机。有多路原图时，可在复查页切换本帧图像部件。

```powershell
straintrace-capture find-frames "E:/runs/test" --camera sim:0 --phase 2 --role test --sequence 40-80
straintrace-capture find-frames "E:/runs/test" --camera sim:0 --received-from 2026-11-25T09:30:00Z --received-to 2026-11-25T09:31:00Z
```

自动翻页时沿用首次返回的 `snapshot_ordinal` 和实验标识，分别传给 `--snapshot-ordinal` 与 `--expect-experiment-id`。更早的结果使用 `older_before`，更新的结果使用 `newer_after`，对应 `--before-ordinal` 和 `--after-ordinal`。`null` 表示该方向没有下一页。查询只读取台账中的元数据，每页支持 1 至 256 条记录。

### 导出图像序列

采集结束后，在**复查与分析 → 应变分析**点**导出图像序列**。选择相机、实验阶段和原帧号范围。例如输入 `40-80` 可取第 40 至 80 帧。用**检查范围**查看参考图、实验图数量和空间，再点**导出并核验**。鼠标悬停或聚焦后按 F1 可查看各项说明。

参考图独立选择，排在第 0 张。参考帧序号留空时使用已保存的唯一参考图，无参考阶段时使用第一张实验图。有多张参考图时，在**查找图像**中核对所需原图并填写帧号。后续输出按原帧序号排列，只包含所选范围内晚于参考图的实验图。所有图像须来自同一相机及同一部件，并具有相同的原始像素格式和尺寸。程序还会检查各阶段记录的传感器窗口和采样设置。若需导出辅助部件，可先在复查区切到该部件。

输出目录中的 `images/frame_000000000000.tif` 是参考图，后续文件依次编号。导出逐张复制和核验原始 TIFF 字节，保留采集位深和像素样本。对于 Bayer 原图，按设备记录的像素格式在分析软件配置中选择相应的解码方式。连续编号可用于接受按数字排列的图像文件的工具，例如 Ncorr 或 DICe。 [Ncorr 用户手册](https://www.ncorr.com/download/ncorrmanual_v1_2_2.pdf) [DICe 输入文件说明](https://dicengine.github.io/dice/class_d_i_ce.html)

`frames.csv` 将连续编号与原帧号、阶段、触发事件和收图时刻对应。按原帧号、收图纳秒值或触发事件对照其他采集记录时，可在电子表格中把纳秒时间列按文本导入，保留完整整数。UTC 收图时刻和设备曝光读数分别保留在索引中。携带整个目录和 `capture-sequence.json` 即可独立验证。目标目录必须尚未存在，并在所有 TIFF 核验通过后生成。

```powershell
straintrace-capture export-sequence "E:/runs/test" --output "F:/dic/test-a" --camera sim:0 --phase 2 --sequence 40-80 --check
straintrace-capture export-sequence "E:/runs/test" --output "F:/dic/test-a" --camera sim:0 --phase 2 --sequence 40-80
straintrace-capture verify-sequence "F:/dic/test-a"
```

`--reference-sequence` 指定参考图的原帧号。`--image-part` 指定已记录的完整 GenTL 部件编号。校验发现缺失文件、索引错误或校验值不同时，`verify-sequence` 返回退出码 `4`。

### 制作和核验交接副本

采集结束后，在**复查与分析**的**数据检查与恢复**区打开**制作交接副本**。选择保存位置，再点**复制并校验**。目标是上一级已存在的新目录。可用**添加附件**选入载荷记录、独立脉冲列表或探测器帧表。附件按文件名保存于副本的 `attachments/`。

副本包含原始 TIFF、采集台账、已归档的镜头标定、现有的内部附件，以及 `images/` 中待复查的文件和可用的写入记录。台账保留相机、触发事件、阶段确认和续采关系。原图和标定按台账校验，全部文件另有一份 `capture-transfer.json` 清单。目标盘临时目录内的文件核验通过后才生成交接目录。复制被取消或中断时，用相同的源实验、附件和目标目录重新开始，可重新核验并复用已经复制的文件。SQLite 备份接口生成包含已提交 WAL 记录的独立台账。 [SQLite Backup API](https://www.sqlite.org/backup.html)

完成后点**打开副本**即可复查，标题旁会标记**交接副本**。换电脑时保留整个交接目录，到接收端用**打开实验**选中它，再点**校验图像和台账**。报告分别列出交接清单核验结果和采集过程中的问题。如果在副本上执行了恢复台账等写入操作，再次核验原交接清单时会提示当前内容与交接时不同。

```powershell
straintrace-capture copy-experiment "E:/runs/test" --output "F:/handoff/test" --attach "E:/daq/pulses.csv" --check
straintrace-capture copy-experiment "E:/runs/test" --output "F:/handoff/test" --attach "E:/daq/pulses.csv" --progress
straintrace-capture verify-copy "F:/handoff/test"
```

`--check` 列出复制范围、预计字节数和目标盘可用空间。`--attach` 可重复。`verify-copy` 在清单、文件或所载台账与记录不符时返回退出码 `4`。用于自动化的进度写到标准错误流，最后的结果写到标准输出流。

### 在下一阶段开始前等待确认

现场需要在参考图之后检查夹具、加载准备或触发源时，选用**参考图后确认**模板。也可编辑任一阶段，勾选**本阶段开始前等待确认**，填写现场提示。采前检查会列出等待确认的阶段。

上一阶段的图像全部登记后，主界面顶部显示**确认开始阶段**。在这之前可以查看已保存张数，也可以停止并保存。确认后程序登记确认时间和来源，启动此阶段的相机，并开始该阶段计时。该等待时间不计入阶段时限。硬件触发阶段在确认后仍需等待相机就绪，再发出物理触发。试采从操作员发起时开始，用于测量选中阶段的实际采集和写入表现。

复查时打开**校验图像和台账**，可查看进入等待、收到确认、相机启动或取消的记录。时间来自采集主机。

批处理计划可在阶段里设置 `start_confirmation` 为提示文字。命令行采集会为含确认的计划提供本机状态、确认和停止命令。外部拍摄触发仍由 `--control` 启用。在另一个终端读取状态，再按 `phase_confirmation.phase` 所示的阶段号确认。

```powershell
straintrace-capture status "E:/runs/test" --live
straintrace-capture confirm-phase "E:/runs/test" --phase 2
```

用 `--confirmation-id` 可将命令绑定到状态中显示的那一次确认。返回 `confirmation_requested` 表示请求已接受。若下一阶段使用硬件触发，可在回读监测已配置时用 `wait-hardware` 核对相机就绪。

### 复查同一次触发的图像

在**复查与分析 → 数据检查与恢复**点**触发组复查**。当前图像有触发标识时会直接定位对应组。列表按台账登记顺序分页，可筛选缺帧或冲突。每台相机的原图先核对校验值再显示。缺帧显示空位，重复关联的候选帧号可悬停查看。整次外部脉冲没有登记图像时，可在**校验图像和台账**检查已观测计数之间的断档。

完整组会在具备同一主机时钟记录时显示接收跨度。这个数值取该组最早和最晚的主机收图时刻之差。确认实际曝光同步需要单独核对相机时序。[Basler 采集和曝光触发](https://docs.baslerweb.com/triggered-image-acquisition#frame-and-line-triggers)

### 用独立 DAQ 记录核对漏拍

在已结束的实验中，进入**复查与分析 → 核对脉冲**，选择带有计数器锚点的硬件触发阶段。导入 DAQ 记录的 UTF-8 CSV。`event_number` 列填写实际发出的非负整数脉冲编号。列名不同时可在窗口内选择。若文件含 `phase` 或 `source_id` 列，程序按 Capture 阶段号或信号源筛选。编号上下限可留空，填写时包含边界。

点**开始核对**后，表格列出全部相机缺帧、部分缺帧、编号冲突和仅在台账中出现的脉冲。DAQ 文件覆盖采集首尾时，也可发现完全没有写入台账的首尾脉冲。选择有唯一触发组的脉冲，再点**查看此触发组**，可逐台查看原图和缺帧状态。无法确定脉冲编号的图像会在**未关联图像**中列出，填写编号范围时这里仍显示整个阶段的未关联图像。

**导出核对结果**可保存完整 JSON 或逐条脉冲 CSV。JSON 包含 DAQ 文件校验值、阶段锚点、原 CSV 行号及台账标识。用电子表格打开含长编号的 CSV 时，将编号列按文本导入以保留全部位数。脉冲核对检查编号和帧关联，原图完整性可用**校验图像和台账**查看。

### 开拍时未登记锚点的实验

打开**复查与分析 → 核对脉冲**，选择标有**采后补配**的硬件触发阶段。点**采后补配**，填写 DAQ 信号源、两个独立确认的脉冲编号、各台相机在这两次脉冲对应的原图序号，并记录确认依据。可用**预览两组原图**对照现场标记，悬停查看帧附带的计数值。计数器应经现场核实随同一共享脉冲逐一递增。两次脉冲应来自同一实验和连续计数区间。

选择 DAQ 文件并开始核对。程序检查各台的两张锚点原图、首尾计数差和区间内的计数顺序。两次锚点在 DAQ 文件中各需一条记录。编号范围可留空使用两个锚点之间的全部编号，也可在该区间内缩小核对范围。区间外原图保留在实验中，报告单独列出张数。

用**脉冲差异**查看缺拍和重复计数，用**DAQ 编号缺口**检查 CSV 未列出的编号区间。选中有图像记录的脉冲，点**查看此触发组**，即可校验并排查看相应原图。后续可继续核对曝光时序。补配关系只写入导出的报告。下次可在**采后补配**中载入该 JSON，重新核对同一实验。

### 核对各相机的曝光时序

脉冲核对完成后，点**核对曝光时序**。导入同一次采集、同一 DAQ 时钟记录的共享触发沿和各相机曝光起始沿。填写相机间曝光起始偏差上限、触发至曝光的延迟范围，或同时检查两项。在窗口内用微秒填写限值，最多三位小数。单相机可检查延迟范围。

时序 CSV 使用 UTF-8，每行记录一个信号沿。`event_number` 使用外部脉冲表中的同一编号。`clock_id` 标识本次记录共用的时基，`time_ns` 是从该时基原点量得的整数纳秒。`uncertainty_ns` 为信号沿时刻的绝对误差界，未知时留空。按现场标定考虑采样分辨率及输入、输出和线路延迟。`camera_id` 可用窗口中的**复制相机编号**取得。可用 `phase`、`source_id` 和当前编号范围筛选，也可用 `channel` 保留测量通道。

```csv
event_number,clock_id,edge,camera_id,time_ns,uncertainty_ns,phase,source_id,channel
101,daq-test-1,trigger,,1000000,10,2,DAQ-A,DI0
101,daq-test-1,exposure_start,pylon:12345678,1000500,20,2,DAQ-A,DI1
101,daq-test-1,exposure_start,pylon:87654321,1000650,30,2,DAQ-A,DI2
```

在**曝光时序**列表选中一个脉冲，可同时查看台账帧状态、相机间起始偏差及各相机相对触发沿的延迟。程序报告测得值和按误差界计算的区间。整个区间落在所填范围内才判为符合，横跨限值时显示**无法判定**。点**查看此触发组**可在原图旁看到本组的 DAQ 时序结论。触发沿或曝光起始沿缺失、重复及额外的测量编号均会列出。JSON 保存两份输入的校验值、时基、限值、原始行号及各测量区间。CSV 提供逐脉冲结果。

现场须按相机型号确认信号含义。例如 Basler 滚动快门相机的 `ExposureActive` 输出在首行开始曝光时置位，此时核对的是首行曝光起始时刻。[Basler 电子快门说明](https://docs.baslerweb.com/electronic-shutter-types#exposure-active-signal)

### 按共享脉冲编号对照相机与探测器帧

完成 DAQ 脉冲核对后，点**关联探测器帧**。选择探测器记录导出的 UTF-8 CSV。`event_number` 填两端共同记录的非负整数脉冲编号，`detector_frame` 填该帧的文件名或数据集中的唯一标识。窗口默认选择这两列，也支持自定义列名。混有多个阶段或信号源的记录可填 `phase`、`source_id`，程序按当前核对阶段和范围筛选。

```csv
event_number,detector_frame,phase,source_id
101,scan_001.cbf,2,DAQ-A
102,scan_002.cbf,2,DAQ-A
```

**探测器关联差异**列出各端无记录、DAQ 未列出的编号和重复标识。选中或悬停可查原 CSV 行号。相机有对应图像时可点**查看此触发组**并排校验原图。从**全部探测器关联**可浏览完整记录。若一个脉冲有多条探测器记录，或同一阶段和信号源内重复使用帧标识，该脉冲的关联需人工核实。

点**导出探测器关联**保存完整 JSON 或逐相机 CSV。JSON 保留 DAQ 与探测器文件的 SHA-256、范围、来源行号、采后锚点和各条差异。CSV 每行是一条已确定的相机帧与探测器帧对应关系，允许部分相机缺帧的脉冲导出仍可明确关联的相机帧，并保存状态。`camera_path` 相对实验目录。用脚本读入 `event_number` 时保留整数或原始字符串，避免大编号的浮点舍入。

**存储模式**在输出目录旁选择。默认的**系统缓冲**由操作系统安排 TIFF 数据写回。选择**逐张刷盘**时，程序先同步本批的帧日志，再逐张同步 TIFF 数据并发布，最后提交台账。台账一次处理最多 16 张。**试采**使用同一存储模式，报告会显示模式、实际接收帧率和缓冲峰值。

系统缓冲缩短每批的等待时间，让实时分析更早读取已登记的图像。小幅图像的等批时间更短。适合直接写入的大幅图像可以并行计算 TIFF 校验值。处理大幅图像时，即使前一批台账暂时未提交，后续 TIFF 也可以继续写入。最多有 8 批已写好的图像等待或正在登记，每批至多 16 张，台账按原顺序登记。原图写完即释放像素内存，台账登记后才计入**已存**。中断时，可按帧日志恢复尚未登记且校验一致的 TIFF。

新计划默认使用自动队列。固定队列可能先达到批次上限时，采前报告会提供**改用自动队列**，按当前字节缓冲上限计算待写队列容量。计划中明确填写的固定值按原值执行。对已有尺寸和计划帧率的连续或定时阶段，报告会估算从空缓冲开始、写入暂停时可暂存的收图量，并指出先达到的限制。试采报告和复查页会分别显示待写批次峰值与字节峰值。

在 JSON 计划中，`queue_capacity` 可填 `"auto"` 或正整数。批次上限统计等待写入的批次。`max_buffer_bytes` 限制待写、写入中和事件前缓存的图像像素总字节数。逐张刷盘有时会出现短时积压，持续采集需要输出卷的平均写入速率跟上收图速率。

### 在预览中调整相机

单击要调的相机画面，再点**相机参数**。可修改的项取决于设备回读和当前状态。点击**应用并更新预览**后，程序会短暂停止这一台相机的取图，回读设置并等到该相机送出新画面，再更新采集计划。其他相机继续预览。

**图像质量**会对照调参前后的整幅图像，显示中位亮度和近饱和像素占比。改变传感器采集区域后可重新画局部检查框。相机拒绝或回读不一致时，程序会尝试恢复设定并说明结果。验证后的设置可直接用于试采和正式采集。

### 核对计划中的相机参数

设备空闲时，采前检查读取所选相机当前的参数范围、步长和可选值。报告会指出超限值和对应相机。点**修改相机参数**可定位到该字段。**保存并重新检查**只修改计划。已载入旧计划时，可以移除设备当前不提供的设置。

需要为多台相机设置相同的曝光、增益、像素格式、宽度或高度时，先断开预览，按住 Ctrl 选中相机，再点**多机参数**。窗口显示相机当前取值范围的交集和共同像素格式。悬停字段或聚焦后按 F1，可查看各台的当前值、计划值、范围和步长。只填写本次要统一的参数。设备正在使用自动曝光或自动增益时，可在单台的**相机参数**中关闭对应功能。

点**试设并写入计划**后，程序先检查所有相机，再逐台试设、读回并恢复原值。选择结果中的相机可查看原值、目标和回读值。全部通过后才更新采集计划，下次连接预览或开始采集时应用。更改画幅后，重新核对预览中的测量区及镜头标定。

尺寸与偏移、采样方式、自动曝光和帧率设置之间可能联动。报告会列出需要应用后复核的参数。连接预览可核对实际画面和读回值，试采可继续核对时序与保存结果。[Basler 采集区域说明](https://docs.baslerweb.com/image-roi)

### 按试验机 CSV 阈值保存事件前后原图

在**采集计划**中编辑**事件前后**阶段。填写每台相机要保存的事件前、后张数，以及计划收图频率。点**试验机 CSV 阈值…**，选择试验机正在追加的文件。用载荷或位移列时，程序会尝试从表头识别量名称和单位。确认量值列和原值单位，填写阈值，选择上穿或下穿。可保留试验机时间列的原文。点**使用此阈值**、**应用阶段**，随后检查计划或启动试采。悬停或聚焦后按 **F1** 可查看每个字段的说明。

源文件首行是列名，支持逗号、分号和制表符分隔，支持 UTF-8、带字节序标记的 UTF-16，以及表头含 GB18030 字符的文件。每行是一条完整记录，试验机需要持续追加并写到磁盘。阶段启动后跳过已有内容及当时尚未结束的尾行。相邻两条新增有效记录的数值从低于阈值到等于或高于阈值时判为上穿，下穿的方向相反。无效数值会中断相邻比较。若越线出现在事件前缓存满之前，阶段会继续监看下一次越线。

在**采集监看**可查看是否已经收到新增数据、最近量值及越线状态。表头改变会阻止采前检查，运行中发现文件被截断、替换或已检查的部分被改写时会停用 CSV 监看。需要保存事件窗口时，仍可点**触发一次**。

采集后打开**采集时间线**并选中**CSV 阈值触发**记录。悬停可查看两侧的量值、源文件位置和试验机时间原文。点**查看事件前后原图…**按同一个触发请求定位各相机的事件前、边界和事件后原图。台账记录用于判断的两条源记录的字节位置、长度及 SHA-256。相机帧按主机收到触发请求的时刻与主机收图时刻组织，检测时间还受试验机写入、刷新和操作系统调度影响。测量曝光同步时可使用独立的物理触发与曝光记录。

命令行使用阶段中的 `csv_trigger`。相对路径以配置文件所在目录为基准。运行时会自动监看，`--control` 仅用于另外接收外部命令。

```json
{
  "mode": "event",
  "fps": 10,
  "pre_frames": 10,
  "post_frames": 20,
  "csv_trigger": {
    "path": "mechanics.csv",
    "value_column": "载荷(kN)",
    "time_column": "时间(s)",
    "quantity": "载荷",
    "unit": "kN",
    "direction": "rising",
    "threshold": 5
  }
}
```

从 `timeline` 读取这条记录的 `details.signal_id`，传给 `find-frames --event-context <signal-id>` 可按请求查询原图。

### 同一阶段保存多次事件

编辑**事件前后**阶段，把**事件次数**填为计划次数。填 **0** 可持续等待下一次事件，达到最长时长或点**停止并保存**时结束。默认采集一次。每次事件后收图结束，程序为下一次事件重新积累前图。阶段采用手动触发、外部命令或同一条试验机 CSV 阈值规则。

**采集监看**显示当前事件编号、已完成次数和本次缓存张数。缓存就绪后才接收新的触发。缓存未满或正在收集上一事件的后图时，未接收的请求会计数。CSV 自动触发需要在窗口就绪后再次越线。

页顶在各个标签页跟随当前阶段，显示单次或多次事件的前图缓存、已接收的触发请求和后图进度。CSV 自动监看停用后，如果当前阶段可手动触发，仍可点**触发一次**。开始收集后图后，页顶继续显示这次事件的进度。悬停底部采集状态可查看文件监看故障的原因。

如果相邻触发的间隔较短，在阶段设置中勾选**允许事件窗口重叠**。第一次前图缓存满后，可在前一次事件收集后图时继续用按钮、外部命令或 CSV 越线触发。采集监看会显示同时收图的事件数和是否还可触发。最多有 16 次事件同时等待或收图。达到上限时，拒绝的触发会计数。有计划次数时，接收最后一次触发后会收完已接收事件的后图。

同一张原图只写一次，可同时是前一次事件的后图、后一次事件的前图。触发时已发出拍摄请求、但有相机图像尚未到达的一轮，登记为该事件的边界图。每次事件的台账分别记录前图、边界图和后图。按事件复查、分析和导出时，图像使用该事件中的位置。

触发、事件窗口及共享原图的关联由写入线程登记。采集监看中的收图状态随相机更新。事件收图结束后，待存图像和事件记录可能仍在写入。持续写入不畅导致缓冲区达到上限时，采集停止并报告该次写入故障，已登记的图像可在复查中核对。

结束后从**采集时间线 → 仅看事件窗口**按编号查找。每条记录列出事件前后实际收到的张数和触发来源。双击后可按相机查看这次事件的原图。CSV 触发还保留两条越线样本的量值、时间原文和文件校验值。程序以主机收信时间组织窗口。实际曝光同步需要用相机或独立采样记录验证。

CLI 的 `event_count` 与桌面设置一致，需要窗口重叠时在事件阶段加入 `"overlap_events": true`。外部触发命令可同时指定 `--phase` 与 `--event-window`，使请求只对指定编号生效。完成后用 `timeline --event-windows-only` 查看各次事件的 `details.signal_id`，然后用 `find-frames --event-context` 查看对应原图。有限次数在最长时长前未达到时，运行会报告不足，已保存的窗口仍可复查。正式计划的事件次数排不进试采时限时，试采改为在时限内记录实际能完成的次数。

### 分析或导出某次事件

在**采集时间线**中选择事件，点**查看事件前后原图…**。在查图窗口选好相机，点**分析本次事件…**或**导出本次事件…**。参考图选择窗口会显示本次事件的前图、边界图和后图各有多少张，也会标出候选参考图的原帧号与用途。悬停或按 **F1** 可查看选择的含义。

选用事件之前登记的实验参考图，可以计算本次事件各张图相对于该参考图的变化。选用本次事件中的一张图时，计算使用其后的同事件图像。离线分析打开后会显示事件号与分析帧数。导出文件按原始帧序排列，参考图排在第 0 张，`frames.csv` 中保留事件标识及前图、边界图、后图的标记。可以用核验命令在脱离源实验的目录中检查 TIFF 和索引。

在命令行中，将时间线结果的 `details.signal_id` 传给 `prepare-analysis --event-context` 或 `export-sequence --event-context`。用 `--reference-sequence` 指定参考图片。留空时优先使用唯一的前置实验参考帧，其次使用本事件最早的前图。有多张前置参考帧或本事件只有后图时，请明确指定基准。分析的运行清单会保留事件标识、触发主机时间与各张输入图像的原始校验值。

### 处理触发方式不匹配

**检查计划**、**试采**和**开始采集**会先核对计划需要的触发方式。已连接预览时使用当前设备读到的触发能力。设备空闲时，可读取所选设备的触发节点。报告会列出缺少相应触发能力的设备和阶段，并可直接打开该阶段设置。

普通 USB 视频输入（UVC）在单张、定时、手动和事件阶段按请求取图。程序保留请求后主机从驱动收到的第一张，并在台账中记录请求和收图时刻。可从**检查主机取图计划**打开采前检查，再用试采核对实际帧率和请求到收图的时间。复查页按采集请求关联原图。曝光同步需结合设备时间戳或独立测量核实。

如果单张阶段缺少相机端软件触发，在所有相机都已通过预览确认能连续送图后，可选中该阶段的检查事项，再点**每台取 1 张并检查**。每台相机各自保存收到的第一张。修改保留阶段用途和单帧超时。双相机标定需使用支持对应触发方式的相机。

定时、手动和事件阶段可点**按主机收图选帧并检查**，保留所选阶段的请求方式、频率和张数。有多项建议时也可点**应用全部取图建议**。程序应用后会重新检查整份计划。在阶段设置里也可勾选**缺少软件触发时按主机到达选帧**。采用主机选帧的相机持续送图，支持相机端软件触发的相机按请求拍摄。试采报告显示实际保存帧率和请求到收图的时间。连续送图适配器能统计未被选中的图像时，报告也会列出该计数。

### 设置物理触发输入和脉冲编号

在**采集计划**中编辑**硬件触发**阶段，打开**物理输入与脉冲编号**。各台相机接到同名输入时填写统一名称。接线不同则勾选**逐台指定输入**，在相机所在行填写端口。点**读取设备端口**可查询相机当前允许设置的 `FrameStart` 输入。读取到目录时，采前检查会指出缺少所选输入的相机，并可直接打开该阶段修改。目录未读出时，可按接线填写，再试采核对。支持的相机也可选择厂商提供的 CoaXPress 触发通道，例如 `CxpTrigger0`。[Basler FrameStart 触发](https://docs.baslerweb.com/triggered-image-acquisition) · [Basler CoaXPress 采集卡触发](https://docs.baslerweb.com/frame-grabbers/configuring-the-frame-grabber-using-pylon)

做一次**试采**，在报告中查看各台相机实际回读的输入、触发沿和帧附带计数器。报告给出首末读数及相邻读数的重复、回退和跳阶。查看已保存图像时，悬停在右栏图像信息可读到该帧的原始整数。用试采确认设备实际提供的计数器，并结合现场 DAQ 核实计数规则。

掌握**正式实验同一个已知共享脉冲**的 DAQ 编号及每台相机对应的计数值后，勾选**按共享脉冲编号关联图像**。填写独立记录中的 DAQ 信号源编号、已知脉冲编号、每台相机都记录的计数器及对应值。试采和正式采集分别保留各自的记录。用正式实验编号可在复查页按触发组查看原图，并与独立 DAQ 脉冲表核对。

### 实测目标盘写入

在**检查计划**报告中点**写盘实测**。程序默认选择预估数据率最高且图像规格已知的阶段，也可换成其他阶段。合成图像按当前存储模式保存为 TIFF 并登记台账。图像规格可取自预览、计划参数或匹配的试采，包含各路已保存的图像部件。

测试在正式输出位置所在卷临时写入。达到样本上限、128 轮或约 6 秒写入时间后，程序结束试写，完成剩余刷盘和校验后清理临时文件。

结果显示登记速率、含系统刷盘的原始像素速率和单轮写入耗时的第 95 百分位。后者有助于观察少数写入耗时较长的轮次。已设定固定频率的阶段可直接对照计划数据率。此测量对应本次短时写入条件，可从结果直接进入**试采此阶段**核对相机收图、物理触发和持续写入。

```powershell
straintrace-capture write-probe --config "E:/plans/experiment.json" --output "E:/runs/experiment" --phase 2 --max-mib 128
```

### 使用试采结果

在**采集计划 → 阶段试采**查看各阶段已匹配的试采、设置变化和复核提醒。采前检查后，顶部的试采提示会直接选中建议阶段。建议先复核已有提醒，再试采尚无匹配记录的实验图阶段。尚未试采的参考图和标定图阶段显示为**可选试采**。选中一行可打开试采确认，或重新核对已有试采的台账和原图。取消试采或关闭阻塞报告后，可接着操作原来选中的阶段。完成一次试采后，可从报告打开原图，或返回阶段列表继续。

多阶段计划可点**连续试采**，一次确认阶段列表和每阶段试采时限。默认安排单张、连续和定时的实验图阶段，已有匹配试采的阶段直接沿用其记录。每个新试采阶段按计划顺序单独检查、保存和核验。参考图和标定图阶段可单独试采。

勾选**纳入需确认或触发的阶段**，可在同一个窗口按计划顺序通过这些步骤。进入待确认阶段时，窗口显示原计划中的说明，确认后开始本阶段计时。手动阶段和由操作员触发的事件阶段可点**触发一次**。事件前缓存就绪后按钮可用。配置 CSV 阈值或硬件触发时，界面显示当前等待的信号。试采报告保留阶段确认和 CSV 越线记录。

采前检查遇到阻塞或需要操作员复核的事项时，序列停在该阶段，可从**查看本次采前检查**打开原因。触发阶段到时仍未保存图像时，序列会停下，待核对信号后可重试。点**停止连续试采**会保存并核验已收到的图像。再次运行时，从仍待试采的阶段继续。每次试采的图像和台账可从阶段报告或**最近**打开。

试采图像保存在独立目录，正式采集仍由操作者另行启动。调整阶段、相机或存储设置后，列表会重新对照原记录。通过**检查计划**可加入当前相机回读、预览图像和保存卷的检查结果。需要物理触发的阶段仍由外部设备发送信号。

- 连续或定时试采同时显示帧率、缓冲峰值和采集末段的写入速率。末段两个连续的 2–3 秒区间均按原始像素量比较进入队列和写入并记账的速率，两段写入均低于进入队列速率的 90%，且累计积压增加超过一次写入批次与一轮收图中的较大张数时，提示复查。报告也列出停采后补写的张数。全程平均写入按保存的 TIFF 字节数与总用时计算，含相机连接和队列清空。
- 在试采报告点**核对当前计划**。采前检查会对照原阶段参数、请求的相机设置、GenTL 文件路径、存储设置和输出卷。对于匹配且通过校验的试采，只将实际图像尺寸用于对应阶段的空间估算。当前预览的图像尺寸或格式若有差异，报告会标记变化，并采用预览数据。
- 试采建议根据实际漏拍、触发记录、校验差异、缓冲峰值和写入速度生成。当前计划匹配有持续写入积压的试采时，采前检查会提醒复查，即使试采文件均通过校验。对定时或设置了相机帧率的连续采集，至少保存 10 张图像且平均接收帧率低于设定的 90% 时，报告会提示核对曝光、相机输出上限和传输。该提示对应本次试采时限与设置。
- 有可比的积压测量时，采前报告会给出**建议试采频率**。建议值按两个区间中较低的实测写入速率预留 20% 余量，结合每台相机实测的每帧字节数换算。**试采阶段的建议频率**在独立目录试拍，保存为带有原试采关联的**建议频率复测**。图像与台账校验通过、尺寸和格式一致、每台相机至少收到 4 张且接收跨度达到 4 秒、实收帧率在建议值的 ±10% 内、末段写入充足且缓冲峰值未接近上限时，报告会提供**重新核验并采用频率**。判断积压时，允许停采时有一轮图像仍在写入。
- 重开工作台后，可恢复生成建议时的采集计划，从顶部的**最近**打开**建议频率复测**，再点**频率复测报告**。采用前，程序会重读两次试采的原图和台账，重新比对正式计划与保存卷。遇到图像校验差异或设置不匹配时，报告会给出下一步。通过核验后更新频率并打开采前检查，由操作者另行开始正式采集。
- 定时采集只调整相关阶段的请求频率。对只含连续和单张阶段的计划，程序可按设备允许的取值调整连续收图使用的相机帧率。相机帧率作用于计划中的所有阶段。含其他触发方式的计划可通过更换输出卷或手动调整设置后重新试采。建议保留原阶段的结束条件，正式采集目录由操作者开始采集时创建。
- 手动和事件阶段可点**触发一次**。事件前后窗口需能排入试采时限，且应在触发前留足预缓存时间。硬件阶段等待设备的物理信号，试采的接收时刻和相机计数器可用于诊断。正式实验的脉冲身份和曝光同步需要独立标定或测量。

硬件阶段可勾选**查看相机触发等待输出**，对应计划中的 `monitor_trigger_wait: true`。先在厂商工具中将一路相机输出设为 `FrameTriggerWait`，并确认未启用反相。启动后，画面和进度悬停会逐台显示等待输出。只能读取部分相机时，进度会注明哪些相机尚未核实。每台相机收到首帧后结束这项轮询，采集结束后可在**校验图像和台账**查看回读记录。连续触发时，以采集卡实际连接的等待信号为准。 [Basler 等待信号](https://docs.baslerweb.com/line-source) · [线路状态和反相](https://docs.baslerweb.com/line-status)
- 复查中可以重开**试采报告**。报告重新核对文件和台账。没有收到图像的相机和报告到的丢帧会单独列出。正式计划及目录在试采结束后仍可直接用于正式采集。

### 检查试采原图

试采报告会对各台相机的主图像做全图检查。自动检查每台最多选取 96 张，并参考 64 MiB 的数据量预算。较大的序列按原帧序号均匀抽查，包含首末帧。报告列出范围、核验张数和提醒张数。点**检查试采原图**可按相机查看结果，选一行可读取并核对对应 TIFF。点**检查全部**可逐张复核较大的序列。

设置了采集抽查范围时，试采报告还会列出用保存的原图复核检查框的结果，并显示采集中最近一次的测值。在**检查试采原图**中，可用**查看全图结果**和**查看检查框结果**对照同一帧。用 Shift 重新框选可以临时检查其他位置的亮度和纹理。

从当前计划的试采报告打开原图后，可点窗口下方的**用于采集抽查**，把当前检查框保存给计划中的这台相机。相机离线时也可使用。程序会再次核对原图 TIFF，并与当前计划及可用预览核对画幅。若更改了图像尺寸、主图部件或传感器范围，请在当前预览上重新框选。保存后点**核对当前计划**，可查看按新范围复核的试采亮度结果。

近黑像素按亮度的最低 1% 码值范围统计。近饱和像素按最高 1% 码值范围统计，彩色图像任一颜色通道进入该范围即计入。任一比例达到 20% 时，表格会标记该帧。按住 Shift 在原图拖出检查框，可在相同画幅、格式和图像部件的各帧中重算，并用现有的局部纹理指标排查低对比度或方向性过强的散斑。 [iDICs 数字图像相关技术实践指南](https://doi.org/10.32720/idics/gpg.ed2)

**检查计划**会按阶段显示试采的核验范围和提醒数。配置了计划检查框时，程序会重新校验对应试采的台账和 TIFF，再按当前检查框复核亮度。检查框内达到提醒条件时，**开始采集**会先打开报告供复核。原图校验有差异、画幅不匹配或框内结果不完整时，按全图复核。完整报告保留全图结果。更改计划中的检查框可以用同一批试采原图重算。更改阶段、相机设置或输出卷等条件后，原结果标为历史试采，可在新设置下再试采。

### 采前核对试采回读

正式开拍前，**检查计划**会将匹配的试采与当前相机回读比较。计划准备写入的值会列为**计划应用后再核对**。当前相机身份或可比参数存在差异时，报告会要求复核，并按当前计划或预览估算存储。若各匹配并通过校验的试采对某个手动曝光或增益读数一致、相机身份匹配且当前支持该值，可点**补入试采参数**。这些值只写入当前计划，随后可按新计划重新试采。若选择按当前设置开拍，台账会保存采前差异和确认记录。CLI 可用 `preflight --trial <试采目录> --probe-cameras` 查看同类回读差异。

### 采集后核对试采与正式设置

从工作台开始采集时，正式台账会按阶段保存匹配的试采编号、实际用于采前复核的范围、全图检查结果和开拍前的确认记录。重新打开正式实验，在**复查**点**试采与正式设置**，可查看两次启动相机后读到的参数。例如计划沿用设备默认值时，报告会列出实际曝光或增益的差异。缺少可比回读的项目会单独标记。正式阶段尚未启动时，也可查看开拍前的试采记录。

点**打开关联试采原图**可按阶段找回当时的试采，并按采前记录的抽查或全查范围复核。正式与试采目录一起迁移时会尝试相对路径。单独移动试采目录后，可手动定位，软件会核对实验编号和原帧记录。命令 `python -m straintrace_capture trial-comparison <正式实验目录>` 可读取同一份台账记录。

### 采集棋盘格并拟合镜头参数

1. 选择一台或两台拍摄棋盘格的相机，在**采集计划**点击**标定采图**。填写棋盘格的内角点数和实测方格边长。横排 10 个方格有 9 个内角点。双相机需要一边为奇数、另一边为偶数，确认实际的左右设备顺序。
2. 摆稳棋盘格后点**触发一次**。**棋盘格检查**从已保存的原图识别角点，在匹配的画面上标出绿色圆点。检查识别张数、角点跨度和不同摆位数。双相机只用有明确触发关联且两侧都识别出角点的图像对。
3. 改变棋盘格的位置和倾角，达到默认的 6 个不同摆位后点击**停止并保存**，再点**拟合镜头参数**。程序会从标定实验读取方格尺寸和设备顺序，重新校验原图并保存标定文件。可从**镜头标定**载入文件供后续实验归档。

标定原图和台账存入所选输出位置旁的 `calibration-*` 目录。不同摆位数用于判断能否开始拟合，实际标定精度需用已知几何独立验证。

新标定文件会记录实际图像尺寸、可读的传感器设置和 GenTL 图像部件编号。**切换畸变校正预览**会从已载入的文件中选择匹配的标定。复查已保存图像时优先核对实验归档里的标定，图像来源或几何变化时会恢复原图。若旧标定文件缺少多部件编号，可用原有棋盘格图像重新拟合。[OpenCV 相机标定](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html) · [GenTL 部件偏移和来源](https://www.emva.org/wp-content/uploads/GenICam_GenTL_1_6.pdf)

在**复查与分析**选中相机后点**校正后分析**，从列表选择参考图。程序优先用实验归档中匹配的镜头标定，也可检查已载入的标定或使用指定文件。校正后的参考图和实验图、标定副本及 `capture_binding.json` 存在实验的 `analysis-inputs` 下。Analysis 会载入这组图像，使用独立的结果目录，并在结果清单记录采集绑定和标定校验值。下次可从 Analysis 的**采集联动 → 打开采集绑定**选择该文件。

多部件实验可在**本帧图像**中切换分析所用的部件。在实时分析窗口也可切换，切换后需重新绘制测量区。选定部件的所有输入都按同一编号读取，图像缺失、尺寸改变或原图校验值不符时，程序会报告受影响的帧。结果清单的 `capture_source` 记录实验、相机、部件、帧号和图像校验值。若使用畸变校正，标定文件也须对应所选部件。命令行的 `prepare-analysis`、`follow` 和 `calibrate` 支持 `--image-part`，例如 `--image-part 6/0/0/Mono12`。双相机标定时按 `--camera` 的顺序为每台相机填写部件编号，使用 `primary` 选用主图像。

### 中断后恢复图像

在复查页点**检查中断**。窗口先执行只读检查，显示台账中已登记的帧和 TIFF 张数，以及遗留文件的核对结果。若采集或恢复仍占用实验，等任务结束后点**重新检查**。悬停在统计行可查看各台相机的张数，停在表格行可查看路径、来源行号和判定依据。

点**恢复台账**后，程序重新检查实验标识、写入锁和文件校验值。完整的临时 TIFF 会恢复到原定文件名。验证通过的帧按原序号、时间戳和触发关系登记。窗口随后显示恢复数量及完整原图校验的待复查项。校验失败、缺失或有冲突的帧保持待复查。

### 选择续采起点

在复查页点**准备续采**，或在中断检查窗口点**选择续采起点**。发现待核对的写入记录或台账尚未结束时，会先打开中断检查。台账已经结束且还有可补登记帧或待复查项时，可以先处理这些项目，也可以点**按当前台账续采**。在该按钮悬停或按 F1 可查看目前用于续采判断的记录。

阶段表列出各阶段的方式、用途、台账状态和已保存帧数。若出现中途停止、漏拍、启动失败或尚未启动的阶段，工作台会选中最早需要核对的阶段。悬停或按 F1 可查看各相机帧数及事件。点**查看阶段时间线**可从原记录打开该阶段的图像和触发组。

选定后点**载入续采计划**。新实验会完整执行所选原阶段及后续阶段，并从本轮阶段 1 开始编号。例如从原阶段 3 开始，本轮阶段 1 对照原阶段 3。点**检查计划**，确认相机、参考图、结束条件和新保存位置后再开始。硬件触发配对需要使用本轮核对的脉冲编号和相机计数。新实验归档所用标定和原实验标识。

```powershell
straintrace-capture prepare-continuation "E:/runs/previous" --inspect
straintrace-capture prepare-continuation "E:/runs/previous" --start-phase 3 | Set-Content -Encoding ascii "continuation.json"
straintrace-capture preflight --config "continuation.json" --output "E:/runs/next" --probe-cameras
```

### 核对续采时的相机设置

续采计划会随原实验标识保存相机回读和阶段设置。点**检查计划**，在**续采设置对照**中阅读原实验回读、本次设备回读和计划值。空闲设备的回读反映应用计划前的设置。连接预览后可核对应用计划后的回读。增减相机、改变阶段或改变曝光等参数时，报告会指明相应项目。

点**补入原实验参数**可把报告中列出的设备默认值写成明确的计划值。程序先按序列号或设备路径核对相机，再选择原实验启动时和各已记录阶段中一致、当前设备可读写的值。应用后会重新检查。自动曝光或自动增益启用时，程序对照自动调节模式。硬件触发输入随阶段配置，计数器锚点按本轮测量。 [Basler GenApi 参数访问模式](https://docs.baslerweb.com/pylonapi/cpp/pylon_programmingguide#access-modes-for-parameters)

正式采集开始每个阶段后，台账保存本轮实际回读、对照的原阶段号及设置差异。打开新实验并点**校验图像和台账**即可查看。命令行可用 `preflight --config PLAN.json --output NEW_DIRECTORY --continue-from EXPERIMENT --probe-cameras` 将已有计划与原实验对照。

### 沿用原实验的参考图

打开已结束的续采实验，选中相机和图像部件，再点**离线分析**。选择台账关联的原实验及参考图序号。左侧显示原参考图，右侧显示本轮首张实验图。程序核对相机身份、所选图像部件、像素格式及台账记录的成像区域。核对试样、相机位置和加载基准后，点**使用此参考图并打开分析**。若要以本轮状态为基准，也可点**改用本轮图像**。

Analysis 中第 1 帧为原参考图，后面按本轮实验图序号排列。将分析范围的起始帧设为 1。结果清单记录两轮实验标识、帧标识和输入校验值。采集绑定保存在本轮实验的 `analysis-inputs/continued-…/capture_binding.json`。在 Analysis 的**采集联动 → 打开采集绑定**可重新载入。将两轮目录一起搬移时，保留相对位置即可继续核对原图。

续采相机登记后可点**实时分析**选择原参考图，例如在等待操作员确认时。画好测量区并点**开始跟踪**，程序会在本轮图像写入台账后核对图像部件、像素格式和成像区域，再计算相对于原参考图的应变。曲线的收图时间从本轮首张实验图开始。实时参考图绑定保存在本轮的 `analysis-inputs/live-reference-…/capture_binding.json`，可通过 Analysis 的**采集联动 → 打开采集绑定**重新打开。采集结束后，可用实时窗口的**打开离线分析**沿用这张参考图。

```powershell
straintrace-capture prepare-analysis "E:/runs/next" --camera sim:0 --reference-experiment "E:/runs/previous" --reference-sequence 1 --output "continuation-inputs.json" --template "template.json" --run-config "run-continuation.json"
straintrace-capture follow "E:/runs/next" --camera sim:0 --reference-experiment "E:/runs/previous" --reference-sequence 1 --config "live-roi.json"
```

`follow` 也可用 `--reference-binding` 读取已选的实时参考图绑定。沿用原参考图时，首行以 `is_reference: true` 标记原参考图，收图相对时间为空。本轮实验帧从本轮首张实验图的收图时刻计时，并带有参考图所在实验的标识。

### 保存和导出实时分析结果

点**开始跟踪**后，参考图和每张已计算的实验图都会写入实验目录下 `live-results` 的一份新记录。右下角显示已保存的实验图数量。暂停时可导出已保存的结果。重置后可点**导出实时结果**选择以前的记录，下一次跟踪会另存一份。

CSV 以百分数记录工程应变，并列出帧序号、原图与参考图的标识和 SHA-256、相对收图时间、跟踪质量和实时跳过的累计张数。全场分析记录有效应变点比例和质量标记，载荷对齐已配置时记录相应的载荷和位移。逐帧 JSONL 还保留原始时钟读数、测量区设置及每帧的质量明细。

导出表格标为实时预览。跳过的帧仍可离线重算，跟踪未通过的应变留空。若写入结果失败，窗口会提示，已计算结果仍可在图上查看。CSV 取导出开始时已有的完整记录，原始 TIFF 和采集台账可独立校验。

制作交接副本时，可用**添加附件**选入要随实验移交的 CSV 或 JSONL 文件。

### 用试验机记录对齐载荷

在实时分析中点**载荷对齐 → 选择载荷表**，选试验机导出的 CSV、TSV 或文本。首行需有列名。可识别的列和单位会自动填入，例如 `试验时间 (ms)`、`试验力 (kN)` 和 `横梁位移 (mm)`。有多个候选项时请手动选择。载荷统一以 N 显示，位移统一以 mm 显示。没有位移记录时可留空。

试验机记录带时区的日期时间或 Unix 时间时，选**绝对时间**，并核对两台设备的时钟。记录为相对计时时，填写所选相机的**同步帧序号**，以及两侧同一事件在载荷表中的时间。程序用这个对应关系确定时间零点。选择**主机收图**时用图像到达电脑的时刻，相对计时使用主机单调时钟。选择**曝光中点**时用相机记录的曝光时钟，绝对对齐要求能把它换算到 Unix 时间。已有时钟映射或曝光窗口平均设置时，可用**导入 JSON**。

点**预览匹配**，核对已保存的参考图、首末实验图及同步帧。程序在相邻有效载荷记录间插值。超出时间范围、超过最大插值间隔及无效采样的载荷均留空。能估计采样间隔时，默认建议其三倍作为最大插值间隔。绝对时间表只有表头时，可先应用设置，待载荷写入后开始匹配。相对计时表若改写先前的数据，程序会提示重新核对同步事件。

应用后开始跟踪。逐帧结果和导出表格包含载荷、位移、载荷表中的匹配时间及同步帧依据。

#### 用后到的采样补齐载荷

试验机更新载荷表后，在实时分析底栏点**补齐载荷**，选择同一轮的更新表，再保存新的 CSV。重置后可先选择之前的逐帧记录。程序按记录的图像时钟、载荷列、单位、时间零点和插值上限核对缺失值。表格已有载荷、位移和应变取自对应的实时结果。

补齐时核对早期使用过的采样。新记录按换算后的时间、数值、单位和有效性核对，同一批采样可使用重新导出的表格。旧记录按原载荷表的 SHA-256 核对追加位置。若早期采样已改动或缺失，请核对试验轮次，或用**导出实时结果**查看原记录。

补齐表格用**载荷值来源**和**位移值来源**区分实时匹配与后到采样，并给出原匹配状态、补齐核对状态、两次载荷表的 SHA-256 及补齐所用的采样下标和权重。下标从第一个数据样本的 0 开始计数。仍无采样支持的值留空。

```powershell
straintrace-capture export-live-results "E:/runs/demo/live-results/run.jsonl" --fill-load --output "E:/reports/strain-and-load.csv"
```

若载荷表已移动，可用 `--load-table` 指定同一轮的更新表。命令输出补齐的图像张数和仍缺少有效载荷的实验图数量。

### 在来源实验、续采和复拍之间切换

打开任一实验，在**复查与分析**顶部点**关联实验**。列表按创建时间显示上一轮、更早的实验、后续实验以及同源分支。帧数按相机累计，同一帧保存多路图像时会登记多张 TIFF。选中一行可查看完整目录，悬停或按 F1 可查看各相机的计数。双击一行会先核对实验标识，再打开该目录的复查页。

程序检查实验旁的目录和最近打开过的实验。新建续采还记录原实验的路径线索。整体搬移后，保持目录之间的相对位置就可以继续查找。如果单独移动了某次采集，点**添加搜索目录**选择实验的新位置或它所在的文件夹。旧实验也能用台账中的标识关联。同一个标识出现在多个目录时，列表会显示各目录，供用户选择打开的位置。

关联报告读取台账中的登记记录，各次采集独立保留。要检查 TIFF 文件是否完整，可打开对应实验并点**校验图像和台账**。命令行的 `related` 返回实验标识、关系、状态、帧数及发现的问题。可重复使用 `--search` 指定实验或包含实验的目录，搜索包含所选目录和它的一级子目录。

```powershell
straintrace-capture related "E:/camera-runs/continuation" --search "F:/archive"
```

## Capture strategies

| Mode | Operation |
| --- | --- |
| `single` | One requested image per camera. Use role `reference` or `calibration` as needed. |
| `timed` | Scheduled software requests at `fps`, through a count or duration limit. The scheduler reports missed intervals. |
| `continuous` | Save the delivered stream. Set camera `fps` where supported. Optional count or duration limits stop the phase. |
| `manual` | Wait for the operator or an allowed local command. Multiple calibration views can be acquired in one manual phase. |
| `event` | Retain a rolling window of `pre_frames` per camera, then save the requested `post_frames` after a signal at the configured cadence. Set `csv_trigger` to use new rows of a growing instrument log. |
| `hardware` | Arm a camera's physical FrameStart line. The camera receives the external pulses. Provide `hardware_pairing` when tested counters are known to refer to a shared pulse stream. |

Capture types share the same versioned configuration in the GUI, Python and CLI. A phase with both limits ends on the first limit. UVC single, timed, manual and event modes select the next driver-delivered image after a request. Some UVC drivers provide decoded color and report no exposure clock or hardware counter. Read-backed camera parameters and phase trigger settings are recorded in the ledger.

Set `"software_trigger_fallback": true` on a single, timed, manual or event phase to select the first receipt after each request on devices with a confirmed missing software trigger feature. The camera adapter continues to supply its original image and device telemetry. `pairing` exposes each camera's method and reports `host_receipt_only` for a group using the fallback. The frame record includes the selection request time in `backend_metadata`. The run summary tracks discarded stream receipts in `host_unselected_frames` and checks native counter continuity on the received stream.

## CLI and Python

Use a local, dedicated volume for the experiment directory. The SQLite WAL and raw files remain in the directory during acquisition.

```powershell
python -m straintrace_capture discover
python -m straintrace_capture features sim:0
python -m straintrace_capture validate-config examples/capture/speckle.json
python -m straintrace_capture preflight --config examples/capture/speckle.json --output D:/runs/demo --discover
python -m straintrace_capture preflight --config PLAN.json --output D:/runs/demo --probe-cameras
python -m straintrace_capture preflight --config examples/capture/speckle.json --output D:/runs/demo --trial TRIAL_DIRECTORY
python -m straintrace_capture trial --config examples/capture/speckle.json --output D:/runs/demo --phase 2 --seconds 8
python -m straintrace_capture run --config examples/capture/speckle.json --output D:/runs/demo --progress
python -m straintrace_capture verify D:/runs/demo
python -m straintrace_capture audit-pulses D:/runs/demo --source D:/daq/pulses.csv --phase 2 --output D:/runs/pulse-audit.json
python -m straintrace_capture prepare-analysis D:/runs/demo --output D:/runs/demo-binding.json
python -m straintrace_capture follow D:/runs/demo --config examples/capture/live-rois.json
```

The preflight command reports plan issues and estimates as JSON. Exit code 3 indicates a blocking condition. `--discover` checks the device list. `--probe-cameras` opens and closes the selected physical cameras, reads planned setting constraints and trigger catalogs, and records the connection outcomes under `camera_connections`. `--probe-triggers` is an alias. `camera_settings` records which planned parameters were checked and which require confirmation after applying settings. A connection check failure during `trial` returns the report before creating a trial directory. A confirmed parameter error blocks `run` and `trial` before either creates an experiment directory.

`audit-pulses` reconciles a finished, counter-anchored hardware phase with a DAQ CSV. Name a non-default integer column with `--event-column`. Use `--first-event` and `--last-event` to bound the audit inclusively. A new `.json` output records the input hash and ledger identities. A new `.csv` output lists one row per audited pulse ID. Exit code 0 means the scoped IDs and frame associations agree. Exit code 4 means the audit ran and found discrepancies.

For a finished hardware phase originally recorded without paired pulses, use `--anchor-file anchors.json`. Pass an exported post-capture audit JSON or a JSON object with `schema` set to `straintrace.capture-pulse-anchors/v1`. Supply `experiment_id`, `phase`, `source_id`, `counter_feature`, `first_event_number`, `last_event_number`, `evidence`, and `camera_frames`, which maps each camera ID to its two saved integer frame sequences in that order. The audit binds the evidence to the original run, verifies both anchor TIFFs per camera, and checks the recorded counter progression. Its `complete` result applies to the requested interval within the anchors. Unlisted ranges in the DAQ CSV are included in the JSON report.

To check independently recorded exposure timing, add `--timing-source TIMING.csv` and `--max-skew-ns N`, `--latency-min-ns LOW --latency-max-ns HIGH`, or both limits. All CLI limits use integer nanoseconds. Delays are signed relative to the recorded trigger edge. With timing enabled, `identity_complete` reports the association result and `complete` also requires the timing checks to pass. The command returns exit code 4 when either check finds discrepancies or lacks evidence to pass.

```powershell
python -m straintrace_capture link-detector D:/runs/demo --source D:/detector/frames.csv --pulse-report D:/runs/pulse-audit.json --output D:/runs/detector-links.json
```

With `--pulse-report`, `link-detector` rechecks the source DAQ file and experiment ledger using the exported audit's phase, signal source and range. Post-capture bindings also recheck the original anchor images. If the DAQ file moved, pass its new path with `--daq-source`; the SHA-256 must agree. A new `.json` output retains all pulse outcomes. A `.csv` output writes only uniquely linked camera frames. This mode returns 0 for complete identity coverage and 4 if it writes results with discrepancies. Use `--trigger-source` to perform the direct ledger join and write the original v1 JSON format.

After an interruption, run `recover EXPERIMENT --check` to read committed frame and TIFF counts, verify pending write evidence and list recoverable frames and outstanding issues. This check uses the existing writer lease and reports the saved experiment identity. Run `recover EXPERIMENT` to recheck current evidence, restore verified frames and finalize the ledger. The resulting JSON includes restored identities and unresolved records. Use `run --continue-from EXPERIMENT --config PLAN --output NEW_DIRECTORY` to link a new run with its own plan and frame sequence.

The trial defaults to the first phase marked `test`, or the first phase if there is no test phase. It preserves camera and storage settings. Its time limit applies to the selected phase. For an operator or DAQ trigger, add `--control` and use the trial directory printed to stderr when issuing the `trigger` command. Use `trial-report TRIAL_DIRECTORY` to repeat the integrity check and read the observed cadence and camera features. An unsuccessful start or failed trial exits with 3. A finished trial with incomplete evidence or sustained write lag exits with 4. The `observed` field still reports whether images from each camera passed verification, and `sustained_write_lag` reports whether the writer needs review.

Pass `--trial TRIAL_DIRECTORY` to `preflight` to verify a finished trial and compare it with the current plan. Repeat the option to supply reports for more phases. The newest matching trial for each phase can provide measured frame geometry for the estimate. The desktop preflight uses the latest report read in the current workbench. A change in the plan, configured cameras, storage settings, volume or observed preview geometry is shown in the comparison. A failed matching trial or one with sustained write lag is reported as a warning.

The `rate_suggestions` list contains lower candidate rates for matching trials with sustained write lag, stable geometry and measured receipt cadence. Each entry identifies the source trial, the proposed request or camera rates, the estimated raw load, and the candidate trial duration. Candidate trials started from the desktop link back to the source through `trial.rate_source_experiment_id`.

For local operator or DAQ input, enable `--control` when starting the session, then run `straintrace-capture trigger D:/runs/demo --source DAQ` or `straintrace-capture stop D:/runs/demo`. Command receipts are in the experiment's `control` directory. Authorized remote operators can run the command through their existing login on the Capture host. Capture does not open a network listener. A camera request and the resulting trigger association are separate entries. For confirmed load/displacement samples, `ThresholdTrigger.observe` in the Python API can issue a request on a threshold crossing.

With the operator channel enabled, `straintrace-capture status D:/runs/demo --live` queries the running process. The `phase_progress` object includes the current camera receipt counts and event window. Use `trigger D:/runs/demo --phase 2 --require-prebuffer` to bind a trigger to the second phase and require a full pre-event window. Phase numbers come from the running process, so a trial of any one selected phase uses phase 1. The trigger reply identifies the queued signal. The ledger records its consumption and the `event_window` counts separately. Use `verify` for the integrity of saved files.

In live status, `cameras[ID].pending_write` counts all frames admitted to the writer and awaiting a commit or recorded write failure. `phase_progress.camera_receipts[ID]` contains the current phase's `saved` frame count, `last_receipt_age_s` and `host_receive_fps`. Receipt age is null until that camera first delivers an image in the phase. Rate is null until the host has a usable time span over at least two receipts. The pre-event rolling buffer is reported by the existing event-window and raw-buffer fields.

On the Capture host, run `straintrace-capture wait-hardware D:/runs/demo --phase 2 --timeout 10` before sending the first external pulse. Enable `--control` and set `monitor_trigger_wait` on that hardware phase. The command returns success when each camera has recently reported its configured wait output and the host has received zero frames in that phase. It includes the selected output line, per-camera readback state and polling age. The host checks that the observations are at most 750 ms old, including a conservative allowance for the local command round trip. Use the wired camera signal for time-critical triggering. [GenICam signal naming](https://www.emva.org/wp-content/uploads/GenICam_SFNC_v2_8.pdf) · [Basler Trigger Wait](https://docs.baslerweb.com/line-source)

## Raw files, integrity and timing

- `capture.sqlite3` contains the versioned experiment, camera, event and committed-frame records. The TIFFs under `images/` store the delivered unsigned pixel samples in uncompressed strips. For 10–14-bit samples, the TIFF container uses 16 bits and the record preserves the significant bit count. Bayer arrays retain their mosaic codes and the record gives the pixel format. In offline Capture handoff, `prepare-analysis --derive-color NEW_FOLDER` prepares Bayer luminance or luminance from RGBa without applying alpha. The Analysis desktop offers the same separate conversion. Four-channel storage supports 8-bit samples. [TIFF 6.0 specification](https://printtechnologies.org/standards/files/tiff-v6.pdf)
- Each committed row includes its stable experiment/camera/sequence identity, optional device counter, trigger relation, role, dimensions, dtype and hash. A reader follows only committed rows. Capture records the descriptor and expected TIFF checksum in `pending-frames.log` before writing the image. Entries for the committed batch can then be cleared.
- Recovery takes the writer lease and checks the descriptor checksum and payload checksum before registering a frame. A complete temporary TIFF is published using its original destination. Files with missing or conflicting evidence are listed for review. Keep the experiment directory together when moving it, including any SQLite WAL file and the frame write journal. [SQLite WAL storage](https://sqlite.org/wal.html#the_wal_file)
- Device ticks, host UTC receipt, host monotonic receipt, operator/DAQ command time and exposure markers have distinct meanings. Exposure midpoint is derived from compatible measured endpoints when present. `export-timing` defaults to exposure midpoint and leaves unavailable UTC time blank. `--time-basis host-receive` explicitly selects a time proxy. Supply bounded measured `--clock-anchors` for device-tick conversion. `align-load` uses the existing campaign gap, unit and invalid-sample rules. `link-detector` joins an event-number table to explicit shared pulse identities and shows unmatched rows on both sides. Add a `mechanics` object to the live configuration, or load it from the live window, to include aligned force alongside the provisional strains.
- A shared software request groups camera results but does not measure exposure skew. Common pulse pairing requires a validated chunk counter and its anchor on each camera. PTP node state and raw clock readings remain available when reported by the device. Record measured clock agreement and TTL latency for the rig in use.
- `segment_frames` optionally places consecutive ranges in separate per-camera subdirectories. Sequence numbers and camera identities continue across segments. By default, Capture closes and atomically publishes TIFFs, then durably commits batches of ledger rows. With `write_through`, Capture stages TIFFs, synchronizes the frame journal once per batch, flushes each TIFF before publication and commits the published frames. The existing batch limit is 16 frames. Use a trial to measure this mode on the intended output volume.
- The pre-event window is relative to receipt of the command or DAQ signal by Capture. A complete pre-event round requires a receipt from every selected camera before the signal. A batch crossing that boundary is saved and labeled `boundary`. The event ledger records the number of complete rounds retained before the signal and received after it. A short pre-window remains visible in the verification result.

## Calibration

Use the calibration image role for a series of different checkerboard poses. With two cameras, hold the board stationary for each pair and use a board with one odd and one even inner-corner count. `calibrate` fits the pinhole model and, for two selected cameras, the extrinsics. It reports view IDs, checksums and reprojection fit diagnostics. Add the resulting profile to `calibration_files` for a subsequent run to retain a checksum-verified copy with the experiment. Calibration uses image coordinates and the specified checkerboard spacing in millimeters. A low fit residual still requires independent physical validation. The **Lens calibration** menu toggles the corrected viewport. `prepare-analysis --lens-profile PROFILE --derived-folder NEW_FOLDER` checks the camera, image size, GenTL part identity and reported phase geometry for each selected frame before creating separate correction TIFFs with the raw and calibration hashes.
