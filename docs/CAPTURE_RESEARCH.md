## Phase handoff and hardware arming

labcams exposes separate commands for saving, software triggering and hardware-triggered acquisition. Micro-Manager sequences applicable instrument settings and relies on hardware triggers for tightly synchronized acquisition. For the Capture handoff, a host-side phase confirmation is recorded before the camera arms. Camera readiness and exposure timing remain independently observed. [labcams command reference](https://github.com/jcouto/labcams#udp-and-zmq) · [Micro-Manager hardware synchronization](https://micro-manager.org/Hardware-based_Synchronization_in_Micro-Manager)

## Pausing software-requested acquisition

Micro-Manager exposes acquisition pause and resume in its acquisition manager. Capture applies the pause between software-requested camera rounds, records the operator transitions, and shifts the remaining host schedule. External pulse association continues to use the hardware phase and its independent pulse evidence. [Micro-Manager AcquisitionManager](https://micro-manager.org/apidoc/mmstudio/latest/org/micromanager/acquisition/AcquisitionManager.html)

## Operator observations

labcams exposes a log-message command. Capture records the observation and its host timestamps in the experiment ledger. Review finds the closest committed receipt on each side per camera using the same host's monotonic counter. UTC identifies the displayed time, while the monotonic counter provides elapsed time across any wall-clock adjustment. [labcams command reference](https://github.com/jcouto/labcams#udp-and-zmq) · [Python time documentation](https://docs.python.org/3/library/time.html#time.perf_counter_ns)

## Acquisition and writing measurements

Micro-Manager documents a monitor for acquisition buffer usage. areaDetector reports file writing performance by file format and write mode. Capture's trial report records the acquired image geometry, receipt cadence, camera readback, buffer peak and checksum verification for the selected phase. Compare throughput only with the same frame geometry and sample format, camera settings, duration, output volume and durability policy. Trigger comparisons also require a shared pulse reference and independent exposure timing. [Micro-Manager memory settings](https://micro-manager.org/Micro-Manager_Configuration_Guide#memory-settings) · [areaDetector file writing performance](https://areadetector.github.io/areaDetector/ADCore/NDPluginFile.html#performance)

Micro-Manager configures the circular buffer in memory units and exposes an overflow flag. areaDetector exposes per-plugin queue occupancy and counts arrays dropped when a callback cannot enter a full queue. Capture pairs a queued batch count with a raw-pixel byte budget. The preflight estimates how long an empty buffer can absorb a completely stalled writer for continuous and timed phases with sufficient plan data. The trial and final ledger retain both peaks. [Micro-Manager buffer API](https://micro-manager.org/apidoc/MMCore/latest/class_c_m_m_core.html) · [areaDetector queue records](https://areadetector.github.io/areaDetector/ADCore/NDPluginDriver.html)

Basler recommends monitoring the camera's Trigger Wait output for hardware triggering. Capture can look for an already configured, non-inverted `FrameTriggerWait` output and sample its camera-reported line status before the first received frame. The desktop and local command expose the age and availability of each observation. Physical input readiness and exposure timing still require records from the acquisition rig. [Basler Line Source](https://docs.baslerweb.com/line-source) · [Basler Line Status](https://docs.baslerweb.com/line-status)

Basler specifies idle acquisition for changing the image region. OpenCV documents that video properties depend on the device, driver and backend. Capture applies a preview edit on the selected camera's owning thread while its stream is stopped. Plan updates follow readable feature confirmation and a fresh frame with the expected geometry. [Basler image ROI](https://docs.baslerweb.com/image-roi#changing-position-and-size-of-an-image-roi) · [OpenCV video properties](https://docs.opencv.org/4.x/d4/d15/group__videoio__flags__base.html)

GenICam defines trigger mode and source under a trigger selector. Capture checks the remote node catalog for a required feature that is structurally absent. Node access in the selected mode, receipt timing, and external wiring can be checked during a trial. [EMVA GenICam SFNC](https://www.emva.org/wp-content/uploads/GenICam_SFNC_v2_8.pdf) · [Basler triggered image acquisition](https://docs.baslerweb.com/triggered-image-acquisition)

Harvesters exposes acquired buffers through its image acquirer. Capture drains the free-running adapter with one pending selection per camera and checks each chosen receipt against the request time. The timing evidence concerns host receipt. Sensor exposure timing uses independent camera telemetry. [Harvesters image acquirer reference](https://harvesters.readthedocs.io/en/latest/reference/harvester_core.html#harvesters.core.ImageAcquirer) · [Basler image acquisition modes](https://docs.baslerweb.com/triggered-image-acquisition)

## Dataset transfer after acquisition

Micro-Manager documents per-image TIFF sets with a separate metadata file, plus multipage OME-TIFF and NDTiff formats that embed metadata. Capture's transfer retains its TIFFs together with a standalone SQLite snapshot and a file manifest for verification at the receiving site. The SQLite backup includes committed WAL records. Publishing the finished directory uses a same-volume rename that refuses to replace an existing target. [Micro-Manager file formats](https://micro-manager.org/Micro-Manager_File_Formats) · [SQLite Backup API](https://www.sqlite.org/backup.html) · [Windows MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw) · [Linux rename flags](https://man7.org/linux/man-pages/man2/rename.2.html) · [macOS rename flags](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/sys/stdio.h)

Capture reuses the camera/sequence uniqueness index for exact and narrow sequence searches and the camera/ordinal index for paginated review. The query returns at most one page of metadata and pins the last visible ordinal during pagination. When an image is opened from the search results, the decoded buffer is the same buffer whose SHA-256 was checked. [SQLite query planner](https://www.sqlite.org/queryplanner.html)

## Setup image quality

Noise, image contrast and saturation can change a focus measure. Capture uses the variance of the Laplacian after light Gaussian smoothing on the same full image or inspection rectangle for a manual focus comparison. The running value is the median of three distinct preview frames. Bayer images use one green sampling lattice for the comparison so the alternating color filters do not create apparent edges. Change only focus during the comparison and confirm the result on the original preview. [Pertuz et al., Analysis of focus measure operators](https://doi.org/10.1016/j.patcog.2012.11.011)

The acquisition watch uses the same raw-code exposure statistics and sharply capped sampling on newly admitted primary images. Its sharpness comparison is relative to a camera, phase and image layout, with a brightness gate. The thresholds define operator advisories. Recorded warnings retain the triggering frame sequence and host receipt, so the operator can inspect the original image for changes in the scene or imaging conditions.

areaDetector supports online statistics within an ROI. Capture carries an explicitly selected specimen rectangle from desktop preview into trial and formal monitoring. It binds the rectangle to the delivered image layout and readable sensor-window fields because a device can move the sensor origin at the same delivered width and height. Monitoring records the first effective range per camera and stage, along with changes of that range and the corresponding frame identity. The stored TIFF contains the full delivered image. [areaDetector statistics](https://areadetector.github.io/areaDetector/ADCore/NDPluginStats.html) · [Basler image ROI geometry](https://docs.baslerweb.com/image-roi#changing-position-and-size-of-an-image-roi)

The host-side exposure suggestion uses the 99th percentile of raw sample codes and the near-saturation fraction from five new frames. The candidate uses the camera's manual exposure range and increment, bounded by the operator limit and configured frame periods where available. The candidate is an estimate from observed brightness. Adoption requires new images to show a change consistent with the exposure direction and larger than the measured frame-to-frame variation. Camera processing, saturation and readout can change the response. [EMVA 1288 Linear, Section 2](https://www.emva.org/wp-content/uploads/EMVA1288Linear_4.0Release.pdf) · [Basler Exposure Auto](https://docs.baslerweb.com/exposure-auto) · [Basler Resulting Acquisition Frame Rate](https://docs.baslerweb.com/resulting-acquisition-frame-rate)

## Saving a preview image

Micro-Manager provides single-image capture and saving in its Snap window. The pylon Viewer can save the current image as TIFF. Capture places its save command below the active preview and retains the raw frame displayed when the command is invoked. The standalone TIFF contains its camera identity, significant bit depth and host receipt time. [Micro-Manager user guide](https://micro-manager.org/Micro-Manager_User%27s_Guide2) · [Basler pylon Viewer](https://docs.baslerweb.com/overview-of-the-pylon-viewer)

ImageJ's synchronized windows can copy a region to several images. Capture can compare a saved preview TIFF with a second file or a frame from the same active camera. It shares the pixel rectangle when the recorded camera identity, delivered layout and available sensor window values agree. [ImageJ synchronized windows](https://imagej.net/ij/docs/guide/146-30.html)

## Reconnecting a preview camera

Basler documents destroying a removed device after camera access ceases and reopening it when available. Capture reopens by camera identity on the affected preview worker. For GenTL, the Harvesters update method releases current acquirers, and GenTL specifies one library initialization per producer per process. Capture refreshes the device lists of the already known interfaces under the shared group lock. GenTL specifies that updating those lists preserves instantiated device handles. [Basler device removal sample](https://docs.baslerweb.com/pylonapi/pylon-sdk-samples-manual) · [Harvesters update reference](https://harvesters.readthedocs.io/en/latest/reference/harvester_core.html#harvesters.core.Harvester.update) · [EMVA GenTL 1.6, Sections 3.1 and 3.3](https://www.emva.org/wp-content/uploads/GenICam_GenTL_1_6.pdf)

## Monitoring active capture

areaDetector exposes plugin queue occupancy and dropped arrays as separate counters. Capture follows the transitions at host receipt, writer admission and ledger commit to show per-camera progress and outstanding writes. The hardware-trigger monitor shows receipt age and peer activity. Independent pulse and exposure records support conclusions about missed pulses and synchronization. [areaDetector queue and dropped-array records](https://areadetector.github.io/areaDetector/ADCore/NDPluginDriver.html) · [Basler stream statistics](https://docs.baslerweb.com/stream-grabber-parameters)

## Triggering an event window from an instrument log

The CSV watcher starts at the file end when a phase arms. It parses complete new records and compares consecutive finite values in the instrument's unit. The event record keeps the source-time text and byte identities of the two rows alongside the host observation and trigger receipt. The host may observe a crossing after the instrument wrote it. Measure physical exposure timing independently using camera telemetry or an external timing reference. [Python CSV dialect documentation](https://docs.python.org/3.14/library/csv.html#csv.Dialect.strict) · [Basler triggered image acquisition](https://docs.baslerweb.com/triggered-image-acquisition)

The areaDetector circular buffer supports repeat triggering with configurable pre- and post-trigger image counts. Capture supports successive event windows and optional overlapping windows. With overlap enabled, it retains the most recent camera rounds and records an indexed association for each event that uses a saved frame. A TIFF can participate in multiple windows with a different position in each. Each event retains its signal source, host receipt time, and CSV row evidence when present. [areaDetector ADCore release notes](https://areadetector.github.io/areaDetector/ADCore_release.html)

## Choosing an event reference for DIC

Ncorr separates the reference image from the ordered images to be correlated. Capture uses the saved event membership to select a camera's sequence. The operator can use an earlier recorded reference for the experiment or an explicit reference within the event to measure changes from that image. Analysis and export keep the original frame identities and the event positions so the selected baseline and the frames compared to it are traceable. [Ncorr v1.2.1 manual, sections 2.2–2.3](https://ncorr.com/download/ncorrmanual_v1_2_1.pdf)
